# 模型池调度与控制台优化工作包

**创建日期：** 2026-09-20  
**工单数量：** 2  
**目标：** 统一模型测试、能力验证和实际解析路由的规则，并优化模型池控制台的信息密度与可读性。

## 工单顺序

1. `01-model-pool-routing-policy.md`：模型池调度策略
2. `02-model-pool-console-ui.md`：模型池控制台 UI 优化

## 依赖关系

- 工单 01 是行为规则工单，优先实施并完成自动化测试。
- 工单 02 不依赖后端接口变更，可以独立开发；最终验收应基于工单 01 完成后的真实模型状态。
- 两张工单都不改变模型供应商凭证格式、数据库租户边界或模型池 API 的权限模型。

## 当前不纳入范围

- 不新增模型供应商。
- 不修改模型供应商 API Key 的加密方式。
- 不改变免费额度的实际配额。
- 不把模型执行迁移到其他电脑或分布式 Worker。
- 不进行整体工作台 UI 重构。

## 完成定义

- 调度规则有唯一、可测试的排序定义。
- 测试连接、能力验证和真实解析对“免费优先、默认保底”的语义清晰可见。
- 模型池 UI 能快速识别模型名称、启用状态、验证状态、额度消耗和路由顺序。
- 自动化测试、类型检查、构建和真实局域网回归均通过。
