# 02: 模型池控制台 UI 优化

**Status:** in-review (2026-09-20) — 模型身份层级、自定义原生复选框、半选状态、额度进度条、异常额度保护和自动化回归已完成；真实局域网四尺寸与截图归档待验收

## 背景

当前模型池界面存在以下问题：

- 模型名称、模型标识和供应商信息层级不清晰，长模型名断行较多。
- 勾选框使用浏览器默认样式，与工作台的方形边框和绿色强调色不一致。
- “已用/总额”只显示文本，无法快速判断剩余额度和接近阈值的模型。
- 表格信息密度较高，但模型身份、额度和状态没有形成清晰的扫描路径。

## 目标

在保持当前“数据中台/工作台”风格的前提下，优化模型池控制台：

1. 提升模型名称和辅助信息的可读性。
2. 统一勾选框、全选、选中行和键盘焦点状态。
3. 将“已用/总额”改为额度进度条，并保留精确数字。
4. 让免费额度告警、验证失败、冷却、禁用和付费状态更容易区分。
5. 保持桌面优先和横向表格，不改成卡片式模型列表。

## 视觉方案

### 字体层级

- 模型显示名：工作台主字体，较当前略大、加粗，限制为稳定的两行布局。
- 原始模型 ID：等宽字体、低对比度，用于识别具体调用名称。
- 服务商名称：小号辅助文字，避免与模型 ID 争夺视觉焦点。
- 表头：使用紧凑的工作台标签字体，保持扫描效率。
- 额度数字：使用等宽数字，避免数值变化导致布局抖动。

### 勾选框

- 使用自定义方形勾选框，不使用浏览器默认外观。
- 未选中：浅色背景、细边框。
- 悬停：边框切换为工作台绿色。
- 选中：绿色填充、深色勾号或明确选中标记。
- 全选状态：支持选中、未选中和半选三态。
- `:focus-visible` 必须有清晰的橙色/绿色外轮廓。
- 保留原生 `input[type=checkbox]` 语义，不能只用视觉装饰替代可访问控件。

### 额度进度条

“已用/总额”单元格改为：

- 顶部显示 `880,685 / 1,000,000`。
- 下方显示固定高度进度条。
- 进度比例使用 `used / total`，限制在 `0%–100%`。
- 正常状态：工作台绿色。
- 接近安全阈值：橙色。
- 额度阻断或已耗尽：红色。
- 付费不限额：显示 `不限额`，使用中性色的开放状态。
- 通过 `aria-label` 或进度语义暴露精确使用比例。

### 表格布局

- 保留横向滚动，避免在桌面端压缩到不可读。
- 模型身份列增加最小宽度，减少无意义的逐字断行。
- 额度列使用固定宽度，保证进度条不导致列宽变化。
- 状态标签保留左侧色条，与现有告警色系一致。
- 选中行使用轻微浅绿色底色，不使用强烈阴影或大面积装饰。

## 实施要求

- 只修改模型池控制台相关 React 和 CSS，不改变 API 请求结构。
- 进度条必须从真实 `quotaUsedTokens`、`quotaTotalTokens` 和 `quotaBlocked` 计算。
- 处理总额为 `null`、总额为 `0`、已用超过总额和非法数值等边界状态。
- 所有按钮、复选框和表格操作保留现有权限控制和禁用逻辑。
- 不能通过隐藏列来规避桌面端布局问题。
- 不引入大型 UI 组件库；优先复用现有工作台样式变量。
- 不改变模型池的排序顺序；排序行为由工单 01 决定。
