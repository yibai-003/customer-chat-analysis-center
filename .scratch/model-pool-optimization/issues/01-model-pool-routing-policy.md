# 01: 模型池调度策略与服务商测试规则

**Status:** in-review (2026-09-20)  
**Created:** 2026-09-20  
**Priority:** high  
**Owner:** backend / model-pool  
**Scope:** 服务商测试、模型能力验证、模型池实际路由

## 背景

当前三个动作使用的选择规则不一致：

- 服务商“测试连接”按默认模型优先，不判断免费额度和模型池可用性。
- “验证默认模型”只验证默认模型。
- 实际解析虽然免费模型优先，但免费模型内部先按到期时间、剩余额度、质量等级等排序，界面中的 `priority` 不是第一排序依据。

这会导致默认模型额度耗尽时，测试连接直接失败；同时用户在模型池界面设置的优先级与实际调用顺序不一致。

## 目标

建立统一、可解释、可测试的模型选择规则：

1. 测试服务商连接时，优先使用当前可用的免费模型。
2. 实际解析时，优先使用可用免费模型，并严格按照调度优先级执行。
3. 默认模型只作为保底，不应因为默认标记自动抢占免费模型。
4. 额度耗尽、能力验证失败、过期、冷却中或被剔除的模型必须自动跳过。
5. 付费模型只有在允许付费且免费模型不可用时才可以进入路由。

## 推荐调度顺序

在指定用途（视觉/文本）内，按照以下顺序筛选和排序：

1. 已启用、已入池、能力验证有效、未被额度阻断的非默认免费模型。
2. 满足同样条件的默认免费模型。
3. 允许付费时，已启用、已入池、能力验证有效的非默认付费模型。
4. 允许付费时，默认付费模型作为最终保底。

每个层级内部按以下规则排序：

1. `priority` 升序，数值越小越优先。
2. 非思考模型优先于思考模型，除非用途策略另有规定。
3. 质量等级由高到低。
4. 剩余额度更多者优先。
5. 到期时间更早者优先，避免免费额度浪费。
6. 连续失败次数更少者优先。
7. 模型 ID 稳定排序，确保结果可复现。

说明：默认模型是保底身份，不再作为排序第一条件；`priority` 是用户可操作的主排序字段。

## 服务商测试规则

“测试连接”只验证服务商凭证和兼容接口，不等价于“验证默认模型”：

1. 优先选择可用免费模型中 `priority` 最小的成员。
2. 没有可用免费模型时，选择可用的非默认付费模型。
3. 仍没有可用候选时，选择默认模型并返回明确的失败原因。
4. 测试结果应记录实际使用的模型、用途、耗时、错误分类和时间。
5. 单个模型额度耗尽不应直接禁用整个服务商。

“验证默认模型”继续只验证默认模型；“批量验证”继续验证用户明确选择的成员。

## 实施要求

- 抽取可复用的候选筛选和排序函数，避免服务商测试与实际路由各自实现一套规则。
- 保留现有额度预算、冷却、失败记录、切换记录和审计事件。
- `quota_exhausted` 只阻断对应模型成员；只有明确鉴权失败时才考虑阻断供应商。
- 路由失败后切换到下一候选时，记录 `switch` 事件及前后模型。
- 错误消息必须能区分：无可用免费模型、付费预算不足、服务商鉴权失败、模型能力验证失败。
- 不允许通过降低安全校验、忽略能力验证或直接重置额度来规避问题。

## 验收标准

- [x] 服务商测试在存在可用免费模型时，不调用默认付费模型。
- [x] 服务商测试在首选免费模型额度耗尽时，自动尝试下一可用免费模型。
- [x] 默认模型失败时，不会阻断同一服务商下其他可用成员。
- [x] 实际路由按照 `priority` 升序选择非默认免费模型。
- [x] 默认模型在非默认模型全部不可用时才被选中。
- [x] 付费模型在免费候选可用时不会被调用。
- [x] 免费候选全部不可用且付费预算为零时，返回明确的预算/无可用模型错误。
- [x] 能力验证失败、过期、额度阻断、冷却中和手动剔除成员均不会参与路由。
- [x] 每次切换和最终调用结果均产生正确的模型使用事件。
- [x] 补充排序、测试连接、额度耗尽切换和默认保底的自动化测试。
- [x] `npm test`、`npm run typecheck`、`npm run build` 全部通过。
- [ ] 使用真实局域网服务商凭证完成一次文本或视觉任务回归，并确认实际命中模型符合排序规则。

## 当前实现证据

- 候选筛选与排序集中在 `src/server/services/model-pool-policy.ts`，实际解析和服务商连接测试共用同一套候选规则。
- 服务商测试返回实际命中的 `modelConfigId`、模型、用途和耗时；供应商记录保留测试时间与脱敏错误。
- 自动化验证：`90` 个测试文件、`694` 个测试全部通过；类型检查和生产构建通过。
- 本工单仍需一次真实局域网回归，重点确认界面“测试连接”和真实解析的实际命中模型、切换事件及付费模型未被误调用。
