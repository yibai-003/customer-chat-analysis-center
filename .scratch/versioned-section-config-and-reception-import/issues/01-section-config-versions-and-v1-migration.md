# 01：全板块配置版本生命周期与 V1 迁移

**Status:** in-review
**Priority:** high
**Risk:** high

## What to build

为所有分析板块建立统一的配置版本生命周期，并把当前线上配置迁移为各板块的 V1。

配置版本需要完整快照字段定义、Excel 表头映射、导出设置、字段依赖、提示词、知识内容和板块业务规则。草稿允许编辑和删除；发布后生成板块内递增版本号，并且不可修改、覆盖或删除。每个板块同时只能有一个当前启用的已发布版本。

管理员可以归档、恢复和重新启用历史版本。启用历史版本只影响之后创建的任务，不能改变或重算既有任务。

迁移采用 expand-contract：先增加版本模型和兼容读取，再登记 V1 并回填任务关联，最后把新任务创建收敛到强制绑定版本。迁移必须幂等，并提供可审计的迁移结果和失败恢复方式。

## Blocked by

None.

## Acceptance criteria

- [x] 所有分析板块支持草稿、发布、启用、归档和恢复。
- [x] 发布时生成板块内单调递增的版本号。
- [x] 已发布版本不可编辑、覆盖或删除，并可永久查看。
- [x] 每个板块同时只有一个当前启用的已发布版本。
- [x] 启用历史版本只影响后续新任务。
- [x] 版本快照包含字段、表头映射、导出设置、依赖、提示词、知识内容和业务规则。
- [x] 模型供应商凭证、额度、冷却和健康状态不进入业务版本快照。
- [x] 当前各板块配置被登记为内容等价的 V1。
- [x] 现有任务绑定到对应板块 V1，不触发重分析或结果改写。
- [x] 迁移脚本可以安全重跑，并输出成功数、跳过数和异常记录。
- [x] 迁移中途失败时可以恢复，不留下无版本或重复版本任务。
- [x] V1 迁移前后的同一历史任务导出结果一致。
- [x] 发布、启用、归档、恢复和迁移均写入审计记录。
- [x] 数据库集成测试覆盖唯一当前版本、版本不可变、递增编号、归档恢复和幂等迁移。
