# 05：接待质检两阶段分析与版本化规则派生

**Status:** ready-for-agent  
**Priority:** high  
**Risk:** high  

## What to build

实现接待流程质检的两阶段分析链路：

1. 视觉模型对截图执行一次客观事实抽取。
2. 统一质检模型基于任务绑定版本的问题目录和知识快照，返回零个或多个问题 ID，以及各问题相关的聊天原文、证据说明和判定理由。

模型输出使用严格结构化 Schema。模型不能返回目录外问题，也不能作为维度、扣分、D 级、总分或等级的权威来源。

系统根据任务绑定版本的结构化规则本地派生维度、扣分、是否 D 级、合计扣分、等级、优化建议和是否待复核。当前程序中的问题条件、扣分和等级规则作为接待质检首个新版本的初始规则。

落实会话开始时间、对话轮数、无问题和证据不足的业务规则。

## Blocked by

- 04：接待质检新模板导入契约

## Acceptance criteria

- [ ] 每条截图记录只执行一次视觉事实抽取。
- [ ] 统一质检模型使用任务绑定版本的提示词、问题目录和知识快照。
- [ ] 模型输出通过严格结构化 Schema 校验。
- [ ] 模型返回目录外问题 ID 时任务进入明确失败或待复核状态，不静默接受。
- [ ] 每个问题输出相关聊天原文、证据说明和判定理由。
- [ ] 维度、扣分、D 级、总分和等级只由本地版本规则派生。
- [ ] 每条启用问题规则必须配置维度；缺少维度时版本无法发布。
- [ ] 任一 D 级问题按版本规则覆盖会话等级。
- [ ] 当前程序规则被登记为接待质检首个新版本的初始业务规则。
- [ ] 参考结果文件中的冲突示例不会覆盖当前程序规则。
- [ ] 完整日期时间无法可靠识别时开始时间留空并标记待复核。
- [ ] 客户消息组到人工客服回复算一轮；未回复尾消息、机器人和系统消息不计完整轮次。
- [ ] 无问题且信息充分时输出 A、总扣分 0、待复核“否”，问题详情和建议为空。
- [ ] 证据不足时不虚构问题，可以标记待复核。
- [ ] 规则纯函数测试覆盖多问题求和、D 级覆盖、等级边界、无问题和待复核。
