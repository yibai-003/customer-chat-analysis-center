# 05: 响应式记录详情工作区

**What to build:** 在保留现有记录查看、解析、复核和图片预览逻辑的前提下，统一宽屏固定详情栏与中等桌面详情抽屉的结构，使详情内容独立滚动、操作区稳定可达，并补齐抽屉模式的模态语义和键盘焦点约束。

**Blocked by:** 04: 分析工作台组件层级与视觉降噪

**Related:** 01: ATELIER 桌面端 UI 实现；02: ATELIER 真实局域网多分辨率验收

**Status:** done (2026-09-19)

## Problem

1. 当前详情抽屉仅依赖 CSS 移出视口，关闭后内部表单仍可能进入键盘焦点顺序。
2. 抽屉打开时缺少明确的 `dialog`、`aria-modal` 和焦点循环约束。
3. 宽屏固定详情栏和中等桌面抽屉共用同一套激活状态，宽屏也会创建无效遮罩节点并触发页面锁定状态。
4. 详情内容与底部解析、复核操作位于同一滚动流，长字段内容下操作按钮不稳定。
5. 详情面板高度与滚动责任分散在基础样式、详情样式和主题样式中，容易出现页面整体滚动或内容堆叠。

## Scope

- 使用 `matchMedia("(max-width: 1199px)")` 区分固定详情栏与详情抽屉。
- 抽屉关闭时设置 `inert` 和 `aria-hidden`，避免隐藏控件进入焦点顺序。
- 抽屉打开时提供 `role="dialog"`、`aria-modal="true"`、Escape、遮罩关闭和首尾焦点循环。
- 宽屏详情栏使用 `role="complementary"`，不创建遮罩、不锁定页面滚动。
- 将详情内容滚动区和底部操作区拆分为稳定的详情壳层。
- 宽屏详情栏和中等桌面抽屉均在工作区高度内独立滚动。
- 保留详情图片预览、辅助字段、字段结果、重试、复核备注和保存行为。

## Out Of Scope

- 不修改详情 API、任务 API、数据结构、权限和保存逻辑。
- 不修改记录列表列定义、筛选、分页或批量解析行为。
- 不新增移动端专用信息架构。
- 不引入新的组件库、焦点管理库或样式依赖。

## Acceptance Criteria

- [x] `1200px` 及以上使用固定右侧详情栏，页面无模态遮罩和滚动锁定。
- [x] `1199px` 及以下使用右侧详情抽屉，关闭状态不可被键盘访问。
- [x] 抽屉打开后焦点进入关闭按钮，Tab 与 Shift+Tab 不离开抽屉。
- [x] Escape、关闭按钮和遮罩均可关闭抽屉，并将焦点返回原记录按钮。
- [x] 详情正文独立滚动，底部解析和保存操作保持稳定可达。
- [x] 长来源字段、长解析结果和复核备注不造成横向溢出。
- [x] `1024x768`、`1366x768`、`1440x900` 和 `1920x1080` 下不存在新增重叠、裁切或页面横向滚动。
- [x] 记录打开、字段重试、单条解析、复核保存和图片预览测试不回归。

## Implementation Result

- 使用媒体查询状态明确区分抽屉与固定详情栏，宽屏不再生成遮罩或锁定页面滚动。
- 抽屉关闭时增加 `inert` 和 `aria-hidden`，打开时提供模态语义、首尾焦点循环和关闭后焦点恢复。
- 抽屉打开时同时隔离顶部栏、任务侧栏和记录内容区，避免焦点或辅助技术越过模态边界。
- 图片预览提升为独立的上层模态，具备首焦点、焦点循环和关闭后焦点恢复；Escape 只关闭当前最上层模态。
- 详情内容与底部操作拆分为 `detail-shell`，正文独立滚动，解析和复核按钮固定在详情区域底部。
- 将记录查看按钮从 `display: contents` 改为真实五列网格按钮，修复 Chrome 中按钮无法获取焦点的问题。
- 切换记录时先清除旧详情，只有新详情请求成功后才打开面板，避免慢请求期间短暂显示上一条记录。
- 无批量解析权限的角色使用独立五列网格，表头和记录内容保持对齐。
- 真实局域网任务在四个目标视口均无页面横向溢出、记录行溢出、详情重叠或操作区裁切。
- 全量验证结果为 89 个测试文件、685 个测试通过。
