# 03: 工作台顶部操作层级与响应式菜单优化

**What to build:** 重构工作台顶部操作区的信息层级，将高频任务操作、低频管理操作和用户操作明确分组；在不改变权限、接口和业务流程的前提下，降低按钮堆叠感，并保证 `1024px` 桌面宽度下所有授权入口仍然可访问。

**Blocked by:** 01: ATELIER 桌面端 UI 实现

**Related:** 02: ATELIER 真实局域网多分辨率验收与缺陷闭环。工单 03 可与工单 02 的验收证据归档并行；工单 03 完成后，需要重新执行受影响的顶部布局验收。

**Status:** in-progress (2026-09-19) — 实现和管理员局域网验收完成，待非管理员真实验收与截图归档

## Problem

当前顶部操作区同时平铺用户信息、刷新、导入、五个管理入口和导出按钮，存在以下问题：

1. 高频任务操作和低频管理操作视觉权重接近，主工作流不够突出。
2. “管理”目前只是分组标签，板块配置、模型配置、账号管理、审计日志和备份管理仍全部展开。
3. 用户身份、角色和退出按钮占用较多水平空间，账号操作与任务操作混在同一层级。
4. 无任务状态仍显示刷新和导出等低价值或不可用操作。
5. 窄桌面不能通过隐藏管理按钮解决拥挤，否则授权用户会失去入口。

## Scope

- 将顶部操作区划分为：
  - 任务操作：导入 Excel、刷新进度、导出结果。
  - 管理操作：单一 `管理` 菜单。
  - 用户操作：用户名、角色和退出菜单。
- `管理` 菜单根据现有 capability 逐项显示：
  - `config:manage`：板块配置、模型配置。
  - `user:manage`：账号管理。
  - `audit:view`：审计日志。
  - `backup:manage`：备份管理。
- 用户菜单显示当前用户名称和角色，退出操作收纳在菜单内。
- 无任务状态：
  - 导入 Excel 保持主操作。
  - 刷新进度不作为主操作，可隐藏或禁用，但不得造成布局跳动。
  - 导出结果保持禁用，不允许触发无效导出。
- 有任务状态：
  - 刷新进度可用，并保留现有刷新中、分析中和任务操作忙碌时的禁用规则。
  - 导出结果仅在当前任务和当前板块均存在时可用。
- `1024px` 及以上桌面宽度必须保留管理入口和用户入口，不得通过 `display: none` 丢失授权功能。
- 菜单支持点击外部关闭、Escape 关闭和明确的键盘焦点。
- 保持 ATELIER 暖纸色、墨线、苔绿主按钮和硬阴影视觉语言。

## Out Of Scope

- 不修改服务端 API、数据库结构、权限 capability 或角色定义。
- 不改变板块配置、模型配置、账号管理、审计日志和备份管理弹窗内部流程。
- 不重做移动端导航。
- 不引入新的 UI 组件库。
- 不修改导入、刷新、导出和退出的业务逻辑。

## Acceptance Criteria

- [x] 顶部只保留清晰的任务操作、一个管理菜单入口和一个用户菜单入口，不再平铺五个管理按钮。
- [x] 导入 Excel 是顶部最明确的主操作；刷新和导出的视觉权重符合当前任务状态。
- [x] 管理菜单仅显示当前账号有权限访问的入口，无权限入口不会出现在 DOM 中。
- [x] 用户菜单正确显示当前用户名称和角色，退出操作仍调用现有退出流程。
- [x] 管理菜单和用户菜单均支持触发按钮打开、再次点击关闭、点击外部关闭和 Escape 关闭。
- [x] 菜单关闭后焦点返回对应触发按钮；使用 Tab 可以访问菜单中的全部可用操作。
- [x] 打开一个菜单时，另一个菜单自动关闭，页面不会同时出现两个顶部菜单。
- [x] 打开管理项后继续使用现有弹窗，不改变弹窗保存、关闭和权限行为。
- [x] 无任务状态下导出结果不可用；刷新进度不会抢占导入 Excel 的主操作层级。
- [x] 有任务状态下刷新、导入和导出继续遵守现有 busy、processing、importJobId 和 capability 禁用规则。
- [x] 在 `1024x768`、`1366x768`、`1440x900` 和 `1920x1080` 下，顶栏不存在横向滚动、按钮重叠、文字裁切或菜单超出视口。
- [x] `1024px` 桌面下管理和用户入口仍可访问，不依赖隐藏 `.ghost` 按钮降级。
- [x] 自动化权限矩阵确认普通操作人员、复核人员、只读人员和管理员看到的菜单内容符合现有权限规则。
- [x] `prefers-reduced-motion` 下菜单不依赖动画完成打开或关闭。
- [x] 登录、导入、刷新、导出、权限、弹窗和详情抽屉既有测试不回归。
