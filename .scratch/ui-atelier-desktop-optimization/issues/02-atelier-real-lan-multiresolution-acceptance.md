# 02: ATELIER 真实局域网多分辨率验收与缺陷闭环

**What to build:** 使用真实局域网登录、真实任务数据和真实权限角色，对第一阶段 UI 实现进行多分辨率验收；对验收发现的布局、可读性、状态反馈和交互缺陷在本工单内修复并留下证据。

**Blocked by:** 01: ATELIER 桌面端 UI 实现

**Status:** in-progress (2026-09-19) — r3 镜像已部署，真实工作台浏览器复测待完成

- [ ] 使用真实局域网入口完成登录，并分别抽查管理员、操作人员、复核人员或只读人员可见的页面入口；权限差异不能导致布局破坏或出现无权限操作。
- [ ] 在 `1366x768`、`1440x900`、`1920x1080` 和 `1024x768` 下分别验收登录页和已导入任务工作台。
- [ ] 在至少一份真实任务中验证长文件名、长来源字段、长模型名、长字段值、空状态、加载状态、失败状态和需复核状态。
- [ ] 在 `1024x768` 下打开任意记录，确认详情抽屉不遮挡主要操作；关闭按钮、遮罩和 Escape 均可用，关闭后焦点与记录选中状态正确。
- [ ] 在记录列表中验证单选、多选、批量解析、状态筛选和详情切换，确认 UI 优化没有削弱既有业务能力。
- [ ] 打开批量解析弹窗，确认模型容量、并发数、批次大小、Token 提示、热点问题配置和提交/取消操作在低高度桌面中均可见且不被遮挡。
- [ ] 检查 `body`、工作台、记录列表、详情抽屉和弹窗不存在非预期横向滚动、内容裁切、按钮溢出或文字重叠。
- [ ] 每个验收尺寸至少保留一张截图，并记录登录角色、任务、板块、触发状态、截图路径和溢出检查结果。
- [ ] 发现问题时补充回归测试或最小化复现步骤；修复后重新执行相关测试、类型检查和构建。
- [ ] 验收证据归档后，将本工单状态改为 `done`；若仍有影响正常业务的视觉或交互问题，不得提前关闭。
