# 客服解析中心 UI 优化规格

**状态：** 第一阶段已实现；工单 02 进入真实验收归档阶段；工单 03 已开启顶部操作层级优化  
**日期：** 2026-09-18  
**目标：** 将 `E:\ui设计\交付` 中的 ATELIER 视觉方向，合并为当前项目可维护、可验证的桌面端 UI 方案。

## Problem Statement

当前项目已经具备完整的局域网业务能力和较清晰的 React 组件边界，但界面仍存在以下问题：

1. 现有像素风格的颜色、字号、边框和阴影缺少统一令牌。
2. 工作台在 1024px 左右宽度下，侧栏、记录列表和详情区域容易互相挤压。
3. 详情区域在窄桌面下继续占据主布局空间，影响记录浏览和批量操作。
4. 登录页、工作台和配置弹窗的视觉语言不完全统一。
5. 交付目录中的 `pixel-ui-v2.css` 是全局覆盖层，直接引入会与现有 `styles.css` 形成长期 CSS 叠加和维护风险。
6. 样机没有覆盖真实数据下的长文件名、长模型名、错误状态、空状态、加载状态和权限差异。

本阶段只处理桌面优先的第一批核心界面，不改变业务流程、接口、数据模型和权限规则。

## Solution

采用 ATELIER 的暖纸色、苔绿色、墨线和植物纸张质感，但以“业务可读性优先”为约束，分层合并：

1. 提取颜色、字体、边框、阴影、状态色和间距为主题令牌。
2. 将 `pixel-ui-v2.css` 中的可读性、尺寸和布局修复择优合并到基础样式，不长期保留完整全局覆盖文件。
3. 保留一份作用域明确的 ATELIER 主题层，所有主题规则挂在统一主题根节点下。
4. 通过少量 React 结构调整支持 1024px 桌面布局：
   - 宽屏保留侧栏、主内容、详情三栏。
   - 窄桌面将详情改为右侧抽屉。
   - 抽屉支持关闭、Escape 关闭、焦点进入和返回原触发记录。
   - 侧栏进入可折叠或紧凑模式，不隐藏关键任务状态。
5. 植物和水彩装饰集中在登录页、空状态和边缘区域；记录表、模型参数和配置表保持平整、清晰、可扫描。

## User Stories

1. As an 内部操作人员, I want to 在登录页看到清晰、统一且不遮挡内容的品牌界面, so that 我能快速确认当前访问的是客服解析中心。
2. As an 内部操作人员, I want to 在 1366px 及以上宽度下同时查看任务、记录和详情, so that 我能减少页面切换。
3. As an 内部操作人员, I want to 在 1024px 宽度下通过抽屉查看记录详情, so that 记录列表不会被详情栏挤压。
4. As an 内部操作人员, I want to 明确看到记录的解析状态、复核状态和操作入口, so that 我能快速判断下一步动作。
5. As an 内部操作人员, I want to 在批量解析弹窗中清楚看到模型容量、并发数、批次大小和风险提示, so that 我能在提交前理解运行成本和影响。
6. As an 内部操作人员, I want to 在长文件名、长来源字段和长模型名出现时仍能看到稳定的布局, so that 动态业务数据不会破坏页面结构。
7. As an 有复核权限的用户, I want to 在详情抽屉中编辑字段、填写复核备注并保存, so that 窄桌面下仍能完成复核闭环。
8. As an 有分析权限的用户, I want to 在记录列表中继续多选和批量解析, so that UI 优化不会削弱现有批处理能力。
9. As an 管理员, I want to 在弹窗打开、关闭和切换时保持清晰的焦点与状态, so that 键盘操作和重复操作不会造成误解。
10. As an 维护人员, I want to 通过统一主题令牌调整颜色、字体和状态表现, so that 后续页面扩展不需要继续堆叠覆盖 CSS。
11. As an 维护人员, I want to 在构建、类型检查、静态检查和组件测试中发现 UI 回归, so that 视觉改造不会破坏现有业务行为。
12. As an 发布验收人员, I want to 在四个桌面尺寸下获得真实页面截图和溢出检查结果, so that 我能确认样机效果已经落到真实应用。

## Implementation Decisions

### 1. 适配范围

- `1366x768`：核心验收尺寸。
- `1440x900`：标准工作台尺寸。
- `1920x1080`：宽屏三栏布局尺寸。
- `1024x768`：最低完整功能尺寸。
- `<1024px`：本阶段不承诺完整复杂表格和配置操作，保留现有降级布局。

布局行为：

- `>=1280px`：侧栏、主内容、详情栏三栏常驻。
- `1024px-1279px`：侧栏进入紧凑或可折叠状态，详情改为右侧抽屉。
- 详情抽屉打开时，背景页面不可滚动；关闭后恢复原滚动位置。
- 抽屉必须有可访问名称、关闭按钮、Escape 关闭和可见焦点。
- 顶栏操作不能通过简单隐藏关键按钮解决溢出；低优先级管理动作可进入明确的更多菜单。

### 2. 主题挂载与 CSS 边界

- 使用统一的主题根节点，例如 `body[data-ui-theme="atelier"]`。
- 弹窗通过 portal 渲染到 `body`，因此主题根节点必须覆盖弹窗。
- 新增主题样式必须使用主题根节点前缀，禁止无前缀的全局组件覆盖。
- 不直接将完整 `pixel-ui-v2.css` 和 `atelier-theme.css` 作为永久并列覆盖层。
- 保留现有类名和可访问性属性；只有在抽屉、顶栏溢出菜单和布局语义不足时新增结构类名。
- 主题令牌至少覆盖：
  - 页面背景、面板背景、墨色、弱化文字、边框色。
  - 苔绿、青色、橙色等状态色。
  - 小控件、按钮、卡片和弹窗的硬阴影层级。
  - 正文、标题、技术元信息和表格字号。

### 3. 第一阶段页面范围

#### 登录页

- 修复植物装饰遮挡品牌标记、标题和副标题的问题。
- 保留 ATELIER 的暖纸、墨线、苔绿按钮和硬边框。
- 登录表单保持稳定宽度，错误提示不能挤压输入框和主按钮。
- 登录态、错误态、未创建账号提示和恢复会话态必须统一视觉语言。

#### 工作台外壳

- 优化顶栏品牌区、用户信息、退出和业务操作按钮的层级。
- 统一侧栏任务、板块、知识库入口和服务连接状态的密度。
- 侧栏装饰不遮挡任务列表、底部服务状态和滚动区域。
- 页面主标题支持长文件名换行，不允许撑破操作区。

#### 任务与记录列表

- 记录表头采用高对比度结构。
- 记录行保持稳定网格，缩略图、记录名称、来源字段、解析状态、复核状态和操作列不得因动态数据发生横向漂移。
- 长来源字段使用截断和可访问的完整文本提示。
- 保留全选、单选、批量解析和清空选择行为。
- 选中态、悬停态、禁用态、解析中、失败、需复核和已完成状态必须可区分。

#### 详情区与详情抽屉

- 宽屏保留常驻详情栏。
- 1024px 桌面改为右侧抽屉，不再将详情堆叠到记录列表下方。
- 抽屉内容继续支持原图预览、辅助字段、字段解析结果、复核备注和保存复核。
- 抽屉关闭后记录选中态仍保留；重新打开显示同一条记录。
- 异步加载、保存中、保存失败和无详情状态必须有明确反馈。

#### 批量解析弹窗

- 保留现有模型容量计算、选中数量、并发数、批次大小、付费 Token 和热点问题设置。
- 指标块、风险提示、输入项和确认操作按“信息摘要、风险提示、参数输入、提交动作”分层。
- 参数输入在 1024px 高度下不能被底部按钮遮挡。
- 提交中必须锁定重复提交，取消动作保持可用或明确显示不可用原因。

### 4. 视觉规则

- 圆角默认保持为 0；只有浏览器原生控件或明确的可访问性需求允许例外。
- 主结构使用 2px 墨线和硬偏移阴影。
- 动效采用短时、低干扰的步进过渡；支持 `prefers-reduced-motion`。
- 中文业务正文不低于 11px，主要阅读文本优先使用 12px 或更大字号。
- 技术元信息可使用较小等宽字体，但不能承担主要业务信息。
- 表格和状态颜色必须同时依赖文字或图形标记，不能只依赖颜色。
- 不在记录表、配置表和弹窗主体使用高透明度植物背景。

### 5. 组件与状态边界

不改变现有业务状态机，只补足 UI 状态表现：

- loading：登录恢复、任务刷新、记录详情加载、批量解析提交。
- empty：无任务、无记录、无筛选结果、无详情。
- error：登录失败、导入失败、解析失败、保存失败。
- disabled：无权限、任务运行中、重复提交、不可用模型。
- drawer：打开、关闭、切换记录、Escape、焦点恢复。
- viewport：宽屏三栏、窄桌面抽屉、低于 1024px 降级。

### 6. 交付顺序

1. 建立主题令牌和基础布局约束。
2. 调整登录页和工作台外壳。
3. 调整任务列表、记录列表和状态表现。
4. 实现详情抽屉及焦点行为。
5. 调整批量解析弹窗。
6. 执行真实数据多分辨率验收。
7. 根据验收结果清理无效覆盖规则和重复样式。

## Testing Decisions

### 自动化验证

实现完成后必须通过：

```text
npm test
npm run typecheck
npm run lint
npm run build
```

已有的登录、权限、记录选择、知识库和弹窗组件测试继续作为行为回归边界。详情抽屉需要补充：

1. 打开记录后显示详情。
2. 点击关闭或按 Escape 后关闭。
3. 关闭后焦点返回触发记录。
4. 无详情、加载中、保存中和保存失败状态可见。
5. 无复核权限时字段和备注保持只读。

### 真实页面验收

使用真实应用、真实登录流程和可用测试数据检查：

1. 登录页。
2. 已导入任务的工作台。
3. 记录选中与详情显示。
4. 1024px 下详情抽屉。
5. 批量解析弹窗。
6. 空任务和无筛选结果状态。
7. 错误提示和按钮禁用状态。

每个尺寸至少保留一张截图：

- `1366x768`
- `1440x900`
- `1920x1080`
- `1024x768`

每个尺寸执行横向溢出检查，重点检查 `body`、工作台主容器、记录列表、详情抽屉和弹窗。验收证据应记录：

- 页面尺寸。
- 当前登录角色。
- 当前任务和板块。
- 触发的 UI 状态。
- 截图路径。
- 是否出现横向滚动或内容裁切。

## Out of Scope

1. 手机端完整适配。
2. 改变解析、复核、导入、导出和权限业务流程。
3. 改变服务端 API、数据库结构和模型池逻辑。
4. 本阶段重新设计知识库、模型池、账号管理、审计日志和备份管理的业务交互。
5. 暗色模式。
6. 引入完整 UI 组件库或替换 React 技术栈。
7. 仅为视觉效果引入新的图片素材或外部在线资源。

### 已确认的设计决策

- 采用 ATELIER 作为第一阶段视觉方向。
- 桌面优先，`1024px` 为最低完整功能尺寸。
- 允许调整少量 React 结构和交互布局。
- 详情在窄桌面使用抽屉，不再单纯堆叠到列表下方。
- 顶部高频任务操作保持直接可见，低频管理操作收纳到单一管理菜单。
- 用户身份、角色和退出操作收纳到独立用户菜单。
- 窄桌面必须保留授权入口，不能通过隐藏管理按钮解决顶部拥挤。
- 以真实页面多分辨率截图和溢出检查作为硬验收门槛。
- 不把两份交付 CSS 直接作为长期全局覆盖层。

### 主要风险

1. 真实业务数据的长文件名、模型名和字段内容可能暴露样机未覆盖的换行问题。
2. 弹窗通过 portal 渲染，主题作用域不完整会造成部分页面颜色不一致。
3. 详情抽屉涉及焦点和滚动锁定，若只做视觉层可能引入键盘操作回归。
4. 现有 `styles.css` 体量较大，迁移时必须避免新增同名规则继续堆叠。

本规格不新增 ADR：主题方向和 CSS 合并方式仍可逆，暂未达到需要长期记录的不可逆架构决策门槛。
