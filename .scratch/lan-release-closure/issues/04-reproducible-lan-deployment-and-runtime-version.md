# 04: 局域网可追溯部署与运行版本一致性

**What to build:** 建立从 Git 提交到 Docker 镜像、局域网容器和浏览器实际资源的可追溯部署流程，避免代码已经推送但局域网仍运行旧镜像。

**Status:** in-review (2026-09-20) — 标准部署脚本、版本接口、就绪 CLI、版本/资源核验、失败回滚和自动化测试已完成；真实局域网发布、浏览器核验及发布/回滚/再发布演练待验收

**Priority:** high

**Owner:** release / lan-operations

**Related:** 03: 同步最新提交并重新生成 CI 发布工件

## 背景

2026 年 9 月 20 日发现：

- 仓库 `main` 已推送最新代码，包含新版登录工作台 UI。
- 局域网入口 `http://172.16.20.178:8788` 仍由 Docker 容器 `lan-preview` 提供服务。
- 容器继续使用旧镜像 `customer-chat-analysis-center:0.1.0-ui-atelier-20260919-r4`。
- 浏览器从服务端取得旧资源 `index-DDiOySyq.js` 和 `index-CcLoK7B3.css`，因此看不到已经提交的新登录 UI。
- 仅执行 `git push` 或重启本地 `npm run dev` 不会更新已经运行的 Docker 镜像。

这说明当前发布流程缺少以下约束：

1. 运行容器没有明确记录对应的 Git commit。
2. 镜像标签没有强制绑定完整提交 SHA。
3. 本地源码服务和 Docker 局域网服务的端口与运行来源不够显式。
4. “重新拉起项目”没有自动完成构建、替换、健康检查和版本核验。

## 目标

建立一个可重复执行、可回滚、可验证的局域网发布入口，使每次发布都能明确回答：

- 当前运行的容器来自哪个 Git commit？
- 当前运行的镜像标签和镜像 ID 是什么？
- 浏览器实际加载的 JS/CSS 是否来自本次发布？
- 数据库、知识库、模型凭证和备份是否保持不变？
- 新版本失败时如何恢复上一个健康版本？

## 实施范围

### 1. 版本标识

- 镜像标签必须包含短 commit SHA，例如：
  `customer-chat-analysis-center:0.1.0-504f020`
- 容器环境变量或只读运行信息接口必须暴露：
  - 完整 commit SHA
  - 构建时间
  - 镜像标签
  - 应用版本
- 前端构建产物必须能够通过入口 HTML 或健康/就绪接口确认资源版本。

### 2. 标准部署脚本

新增统一的局域网部署入口，例如：

```text
scripts/lan-deploy.ps1
```

脚本至少完成：

1. 检查工作区状态和当前 commit。
2. 阻止未提交改动直接作为正式局域网版本发布，除非显式传入预览参数。
3. 执行必要的测试、类型检查和生产构建。
4. 使用 commit SHA 构建镜像。
5. 记录当前运行镜像作为回滚目标。
6. 保留数据库、知识库、上传文件、导出文件和密钥目录。
7. 使用固定配置替换局域网容器。
8. 等待 Docker healthcheck 和 `/api/ready` 通过。
9. 检查容器版本、镜像标签、commit 和浏览器静态资源一致。
10. 输出局域网访问地址、当前版本和回滚命令。

### 3. 运行时版本检查

- 增加可读但不泄露凭证的 `/api/version` 或等价运行信息。
- `health` 只表示进程存活；`ready` 必须同时确认数据库、迁移和必要目录可用。
- 部署脚本必须拒绝以下情况：
  - 容器版本不是目标 commit。
  - 入口 HTML 引用旧构建资源。
  - 健康检查未通过。
  - 数据目录挂载不符合预期。

### 4. 回滚机制

- 部署前保存当前容器名称、镜像标签和镜像 ID。
- 新版本在超时、健康检查失败或版本核验失败时自动回滚。
- 回滚不得删除或重建业务数据目录。
- 回滚后再次执行健康检查和版本核验。

## 不在范围内

- 不修改认证、权限、多用户隔离或模型池业务逻辑。
- 不迁移 SQLite 到服务型数据库。
- 不把任务执行迁移到其他局域网电脑。
- 不在本工单内实现完整 CI/CD 平台；只要求为后续 CI/CD 接入保留可调用的标准脚本和版本接口。
- 不自动重置管理员密码或模型供应商凭证。

验收记录至少包含：

- 镜像标签和镜像 ID。

## 回滚要求

- 标准脚本必须支持通过指定旧镜像标签回滚。
- 回滚只切换应用容器和镜像，不删除业务数据目录。
- 任何版本核验失败不得覆盖当前健康版本。
- 回滚完成后必须输出实际运行的旧版本 SHA 和镜像标签。
