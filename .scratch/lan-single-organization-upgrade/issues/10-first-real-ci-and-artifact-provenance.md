# 10: 首次真实 CI 与发布工件追溯

**What to build:** 将当前局域网实现及质量工作流完整纳入版本控制，在远端执行第一次真实 CI，并验证发布候选工件与通过质量闸门的提交、镜像标签和镜像 ID 一致。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 审查当前工作区，将局域网实现、迁移、测试、Docker、部署、运维文档和 CI 工作流纳入提交；不得提交 `.env`、真实密钥、业务数据、备份、测试证据中的敏感值或本地临时目录。
- [ ] 推送的提交在干净的 GitHub Actions runner 中依次通过 `npm ci`、`check:installation`、测试、类型检查、lint、构建、数据库初始化/检查和冒烟检查。
- [ ] 任一质量步骤失败时发布候选作业不会运行或不会产生可误用的成功工件。
- [ ] 发布候选作业构建生产镜像但不自动部署，不登录或推送未批准的镜像仓库。
- [ ] 下载并检查发布工件中的 `manifest.json`，确认完整提交 SHA、版本、工作流运行 ID、镜像标签和镜像 ID 与本次成功运行一致。
- [ ] 工件包含启动所需的已构建资产或明确依赖镜像运行，不把一个缺少运行文件的源码压缩包描述为可直接部署包。
- [ ] 首次 CI 运行 URL、提交 SHA、工件名称、清单摘要和检查日期记录到局域网发布验收文档。
- [ ] 本地与 CI 的 Node 主版本、锁文件和迁移版本一致；发现平台差异时修复后重新运行，不以本地通过替代 CI 通过。
