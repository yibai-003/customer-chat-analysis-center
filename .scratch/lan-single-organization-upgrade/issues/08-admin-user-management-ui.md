# 08: 管理员账号管理界面

**What to build:** 在现有账号管理 API 和 capability 模型之上，交付管理员可直接使用的账号管理界面，覆盖账号列表、创建、角色修改、启用/停用和密码重置，并正确处理最后管理员保护、会话撤销和并发更新后的状态刷新。

**Blocked by:** None (can start immediately)

**Status:** done (2026-09-17)

- [x] 只有具备 `user:manage` capability 的用户能看到并进入账号管理界面；其他角色没有入口，直接调用账号管理 API 仍返回 403。
- [x] 管理员可以查看账号、角色、启用状态和更新时间，但页面及网络响应不显示密码哈希、会话标识或其他凭据。
- [x] 创建账号表单支持五类角色，执行与服务端一致的用户名、显示名和初始密码校验，并在成功后刷新列表。
- [x] 管理员可以修改显示名、角色和启用状态；停用账号或重置密码后，该账号的既有会话立即失效。
- [x] 停用或降级最后一个启用中的管理员时，页面展示服务端拒绝原因且保持原状态，不能出现界面已成功但数据库未更新的假状态。
- [x] 密码重置采用二次确认，不回显旧密码，不把新密码写入日志、URL、本地存储或长期前端状态。
- [x] 会话失效、403、网络失败和重复提交均有确定处理；失败时不关闭仍需修正的表单，也不保留错误的乐观状态。
- [x] 前端组件测试覆盖入口显隐、账号创建、角色修改、停用、密码重置、最后管理员保护和拒绝后的状态恢复；现有 HTTP 权限矩阵继续通过。

**实现摘要（2026-09-17）：**
- 新增 `src/client/components/admin/UserManagementDialog.tsx`：账号列表（用户名、显示名、角色、启用状态、更新时间）、创建表单（五角色 + 与服务端一致的校验）、行内编辑显示名/角色、停用/启用、密码重置（新密码 + 确认 → 二次确认弹窗）；所有变更后重新拉取服务端列表，失败时展示服务端原因并刷新，不保留乐观假状态。
- 密码只存在于组件短期状态：成功或关闭即清空；不写入 URL、`localStorage`、日志，网络请求体之外不出现在任何位置（测试断言）。
- 入口接入：`App.tsx` 顶栏在 `can("user:manage")` 时显示“账号管理”，`useWorkspaceController` 的对话框状态扩展 `"users"`；403/401 沿用会话失效与访问拒绝广播，弹窗随之关闭。
- 测试：`UserManagementDialog.test.tsx` 11 项（凭据不泄漏、创建校验/成功/拒绝/重复提交/网络失败、角色修改、停用确认、最后管理员保护、密码重置二次确认与不落盘）；`capability-gating.test.tsx` 增加账号管理入口显隐断言。全量 641 项测试、类型检查、lint、构建与冒烟均通过。
