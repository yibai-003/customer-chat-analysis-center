# 客服解析中心

导入包含聊天截图的 Excel，结合辅助字段调用 OpenAI 兼容视觉模型解析，并导出包含原图和结构化结果的新 Excel。

## 启动

```powershell
npm install
Copy-Item .env.example .env
npm run build
npm run dev
```

打开 `http://localhost:8787`。

也可以使用统一启动脚本：

```powershell
.\scripts\start-local.ps1
```

开发时若单独启动 Vite，`5173` 已配置 `/api` 代理到 `8787`；个人使用推荐先执行
`npm run build`，再使用 `npm run start`，由 Express 同时提供页面和接口。

手动备份本地数据库和知识库快照：

```powershell
npm run backup
```

数据库备份保存在 `data/backups/`，默认保留最近 7 份，可通过 `BACKUP_RETENTION` 调整。
检查数据库完整性和知识库统计使用 `npm run db:check`。恢复知识库配置使用 `npm run knowledge:restore`；
该命令不会恢复聊天任务和模型 API Key。

## 知识库随 GitHub 同步

页面导入、编辑或删除知识库，以及保存板块和字段配置后，服务会自动更新
`knowledge/catalog.json`。该文件纳入 Git 管理，包含知识条目、列用途映射、
板块及父子关系、提示词、字段依赖、知识库绑定和导出设置。中文以 UTF-8 保存。
内部 ID 保持稳定，迁移后字段无需重新选择知识库。

数据保存到本地 JSON 后，运行以下命令提交并上传到当前分支：

```powershell
npm run knowledge:push
```

首次需安装 Git、登录目标 GitHub 账号，并配置 `git config user.name` 和
`git config user.email`。`origin` 必须指向目标 GitHub 仓库。命令会重新导出、
只提交知识快照文件，然后执行普通 `git push`；已有本地提交也会随当前分支推送。
不会强制推送。推送失败时本地快照仍保留，可修复登录或先处理远端更新后重试。
应用保存不会自动联网推送；需执行上述命令后，其他环境才能拉取到变更。
同步功能的代码本身需要先提交到仓库一次。

新环境使用：

```powershell
git clone https://github.com/yibai-003/customer-chat-analysis-center.git
cd customer-chat-analysis-center
npm install
npm run build
npm run dev
```

首次启动会自动恢复仓库中的知识库、板块及字段配置，并重建全文检索索引。
无需重新上传原始知识 Excel。模型 API Key 仍需在新环境单独配置。

已有环境更新时，先运行 `npm run knowledge:push` 保存本机配置，再停止服务、
执行 `git pull --ff-only`，最后重启。仓库快照变更且本地无未同步修改时自动恢复。
服务运行期间拉取到新快照会阻止继续编辑配置，提示先重启，避免旧数据库覆盖新文件。
若本地和仓库各有修改，会报告冲突并保留两边数据；先合并 JSON（保留版本号和关联 ID），
再在停止服务后运行 `npm run knowledge:restore`，明确采用合并后的仓库配置。
恢复前会将整个旧数据库备份到 `data/backups/`，恢复使用数据库事务，失败时回滚。

也可以运行 `npm run knowledge:export` 手动生成快照后自行提交。
快照不包含模型账号/API Key、聊天截图、任务、分析/复核结果、知识导入历史或机器文件路径。
`data/` 和 `.env` 继续被 Git 忽略；知识条目内容本身会作为仓库内容上传。
这是知识配置同步，不是多环境业务数据库实时同步。

首次使用时，在页面的“模型配置”中填写：

- Base URL，例如 `https://your-endpoint.example/v1`
- API Key
- 模型名称

至少保存并启用两种模型角色：

- 视觉模型：用途选择“截图提取模型”，模型必须支持图片输入，并设为该用途的默认模型。
- 文本模型：用途选择“字段分析模型”，用于无图片的 AI 字段和知识路径匹配，并设为该用途的默认模型。

两个角色可以指向同一个兼容接口或模型，但必须分别配置用途默认值。知识提取字段不调用模型。完成两种默认模型配置后，再导入 `.xlsx` 文件。

## 知识库操作

知识库按解析板块隔离。进入板块右侧的“知识库”入口后：

1. 新建或打开该板块的知识库，选择要导入的 Excel。
2. 在预览中确认表头和数据行，再为每一列设置用途。动态表头不要求固定名称，可设置为 `result`、`search`、`keyword`、`description`、`positive_example`、`negative_example` 或 `metadata`。
3. 至少配置一个 `result` 列。层级原因表可以为一级、二级、三级列同时设置 `result` 和 `search`，关键词列设置 `keyword`。
4. 检查新增、更新、跳过、重复行和错误信息，确认后执行导入。再次导入会按完整结果路径增量更新，不会删除本次文件中没有出现的旧条目。
5. 使用“检索测试”输入截图解析结果和辅助字段，确认候选路径、命中内容和排序。检索测试只执行本地召回，不调用分类模型。

## 配置知识字段链

在板块配置中按依赖顺序创建字段：

- 截图解析：`ai`，开启图片解析，使用视觉模型。
- 原因路径匹配：`knowledge_match`，选择知识库，依赖截图解析；这是内部字段，关闭导出。
- 一级选项、二级选项、三级选项：`knowledge_extract`，分别选择原因路径匹配和对应知识列，开启导出。

运行时只对截图解析调用视觉模型，对原因路径匹配调用一次文本模型。三个 `knowledge_extract` 字段直接从同一个匹配快照取值，不会再次调用模型，因此三个结果始终来自同一条完整知识路径。

## 运行与导出

导入包含嵌入聊天截图的 Excel 后，选择板块和记录，先单条试跑确认字段链，再执行批量解析。解析完成后可在详情面板查看截图、辅助字段、字段状态和依据，并保存人工复核结果。

点击“导出结果”会保留原始工作表、辅助字段和嵌入图片，追加已启用且允许导出的结果字段，以及解析状态、复核状态和复核备注。知识匹配内部字段不会写入导出文件。

大文件导入会先创建后台导入任务，上传接口会立即返回导入任务 ID。页面通过进度弹窗显示图片处理、记录创建和失败图片数量，导入完成后再生成可解析任务。当前导入 Worker 和导入预览已使用 XLSX ZIP 条目读取工作表、绘图关系和图片媒体，图片逐张写盘，不再通过 ExcelJS 一次性展开全部媒体；ExcelJS 仍保留用于兼容路径和导出。

每个解析任务会绑定导入时选择的板块。任务绑定后不能使用其他板块解析；旧的未绑定任务会在第一次解析时自动绑定。批量任务支持暂停、取消和仅重试失败记录，重复点击不会同时启动同一任务。

同一条记录在不同板块下的人工复核结果和复核备注会分别保存。导出多板块结果时按板块读取对应结果，不会互相覆盖。

模型配置按“截图提取模型”和“字段分析模型”分开管理。每种用途都可以配置主模型和备用模型；主模型请求失败时按启用配置顺序自动降级到备用模型。知识库匹配会对相同字段、依赖输入和候选集进行短时缓存，知识库内容变化或服务重启后不会继续使用旧缓存。

## 批量解析性能

记录列表按页加载，默认每页 50 条，最多 200 条；状态筛选由服务端执行，因此浏览器不会一次性保存整个任务的记录和缩略图。

批量解析会分批从数据库读取待处理记录。`ANALYSIS_BATCH_SIZE` 控制默认批次大小，`ANALYSIS_CONCURRENCY` 控制默认模型请求并发；启动批量解析时，页面会先根据 CPU、可用内存、数据盘空间和其他运行任务显示本机推荐值，当前任务可以单独调整并发和批次，不会修改环境变量。

运行参数范围为并发 `1-6`、批次 `5-100`。推荐值只反映本机资源，无法检测模型供应商的 RPM、TPM 或并发限制；如果接口返回限流或超时，应降低并发和批次大小。暂停只阻止新记录开始，正在执行的模型请求完成后任务暂停；取消和失败重试保持现有入口。

## 环境变量

- `PORT`: 服务端端口，默认 `8787`
- `DATA_DIR`: 上传、图片和导出文件目录，默认 `./data`
- `DATABASE_PATH`: SQLite 文件路径，默认 `./data/app.db`
- `ENCRYPTION_KEY`: API Key 加密密钥，生产使用时必须替换
- `MAX_UPLOAD_MB`: 单文件大小上限，默认 `2048`（单位 MB）；大文件还需要保证 `DATA_DIR` 所在磁盘有足够空间
- `ANALYSIS_CONCURRENCY`: 批量解析默认 AI 并发数，默认 `2`
- `ANALYSIS_BATCH_SIZE`: 批量解析默认每批记录数，默认 `20`，允许 `5-100`
