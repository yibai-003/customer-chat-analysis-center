# 配置化板块与普通字段

## 工单

- GitHub Issue: #11
- 分支: `feature/config-driven-sections`
- 状态: 实施中

## 背景

平台的每条导入数据都以一张唯一的长聊天截图为核心。Excel 行中的辅助列、截图内容、字段提示词、知识库匹配结果和人工复核结果共同组成一条分析记录。当前系统已经具备配置版本和字段执行器，但字段编辑仍主要写入实时配置表，普通导入会把外部表头回写到板块配置，导致版本编辑、导入和历史任务之间的边界不够清晰。

## 目标

1. 普通字段和通用板块流程由配置版本驱动。
2. 新增、删除、排序、改名和调整普通字段时，不需要修改数据库表结构或业务代码。
3. 字段 `key` 是稳定身份。标签、提示词、输出表头可以调整；改变 `key` 视为删除旧字段并新增新字段。
4. 复杂业务算法保留为服务端注册执行器。未成交归因、接待质检等专用流程继续使用专用执行器和校验规则。
5. 草稿可以完整编辑，发布后不可变；新任务绑定当前发布版本，历史任务继续使用原版本。
6. 导入、分析、人工复核和导出均使用任务绑定的配置版本。
7. 普通字段支持文本、数字、布尔和结构化对象结果；普通 AI 字段的图片解析默认关闭，可在字段级开启。
8. 字段数量不设置应用层固定上限。仍保留单字段提示词、依赖深度、知识条目、上传大小、内存和磁盘预留等资源边界。

## 非目标

- 不允许在配置中执行任意 TypeScript、JavaScript、SQL 或模板代码。
- 不把复杂算法强行拆成通用提示词字段。
- 不改变每条记录必须有唯一聊天截图的业务约束。
- 不用配置版本替代模型供应商凭据、运行态健康信息、调用预算或其他敏感运行状态。
- 不在本工单中修改历史业务数据、生产数据库或真实业务工作簿。

## 核心模型

### 配置版本

板块配置版本包含以下快照：

- 板块基础信息、板块提示词和输入表头定义；
- 普通字段快照；
- 字段依赖快照；
- 导入契约；
- 导出列和行模式；
- 知识库及知识条目快照；
- 专用业务规则快照。

配置版本状态为 `draft`、`published`、`archived`。只有草稿可编辑；发布时执行完整校验。当前版本只影响新建任务，任务创建后保存 `sectionConfigVersionId`，历史任务不跟随当前版本变化。

### 普通字段

普通字段至少包含：

- 稳定 `key`；
- 显示名称和提示词；
- 结果类型；
- 是否必填；
- 是否启用图片输入；
- 字段依赖；
- 是否导出及目标表头；
- 执行器类型。

默认普通 AI 字段不启用图片解析。执行器类型为 `ai` 时使用通用字段执行器；知识匹配、知识提取和已有未成交/接待专用能力使用注册执行器。服务端必须拒绝未注册的执行器类型。

字段依赖只能指向同一版本中的字段 `key` 或配置的外部输入表头，必须拒绝自依赖、缺失依赖和循环依赖。字段 `key` 重复时不能发布。

### 导入契约

通用板块版本保存：

- 唯一聊天截图列；
- 必需外部输入表头；
- 可选外部输入表头。

导入规则：

- 聊天截图列和必需表头缺失时，预览失败或返回明确的缺失字段列表，不能创建任务；
- 可选表头缺失时继续导入，对应记录值为空；
- 表头存在但单元格为空时，按字段的必填和执行结果校验处理，不把“可选输入”升级为导入错误；
- 外部多出的表头保留在该记录的 `sourceFields` 上下文中，但不会自动加入板块版本，也不会修改实时板块配置；
- 每个可识别的聊天截图只产生一条记录，截图锚点继续作为记录边界；
- 接待质检继续使用其版本化的专用导入契约、历史结果冲突判定和截图列兼容逻辑。

### 导入、分析和导出边界

1. 选择板块时默认选择当前发布版本；没有发布版本时不能进入依赖版本的导入流程。
2. 导入预览和实际导入必须使用同一个 `sectionConfigVersionId`。
3. 分析任务只读取任务绑定版本中的字段、提示词、依赖、知识库和业务规则。
4. 导出列完全由任务绑定版本的导出设置决定。通用版本创建时可带平台和会话 ID 等基础列；运行时不得根据当前实时字段补列。
5. 已存在的任务和分析结果不因后续发布、归档或启用其他版本而改变。

## 配置工作流

1. 从当前发布版本或当前初始化配置创建草稿。
2. 在草稿中编辑板块信息、导入契约、普通字段、依赖和导出设置。
3. 保存时做结构校验；发布前做完整校验并报告所有关键错误。
4. 发布后版本冻结，作为新任务的绑定来源。
5. 如需调整，创建新的草稿版本，不能直接修改已发布版本。

旧的字段/板块实时配置接口可以保留作为迁移兼容入口，但配置界面和新流程不得依赖它们保存已版本化的业务配置。版本编辑保存必须是一次完整的草稿快照更新，避免字段逐条写入时出现半成品配置。

## 兼容性

- 现有接待质检的双阶段截图事实、质检分析、专用规则、历史结果导入和截图记录导出行为必须保持。
- 现有未成交分析的归因、派生和话术执行器必须保持。
- 已有版本快照中没有通用导入契约时，按旧板块输入配置生成兼容默认契约；升级过程不得清空历史快照。
- 不为扩展普通字段新增每个字段一列的数据库表结构；字段、导出列和导入契约以 JSON 快照保存。

## 验收标准

### 配置版本

- 可以创建草稿并在草稿中一次保存完整板块、字段、导入和导出配置。
- 草稿可新增、删除、排序和修改普通字段；字段数量超过旧实现的任意固定数组限制时仍可保存、校验、发布。
- 修改字段标签、提示词或导出表头不会改变 `key`。
- 发布版本不可编辑；新版本发布后旧任务仍能按旧版本分析和导出。
- 未注册执行器、重复 `key`、循环依赖、无效导出列和不完整专用规则不能发布。

### 导入和导出

- 预览和实际导入都绑定同一配置版本。
- 缺失必需表头返回具体字段；可选表头缺失或为空不会阻止导入。
- 额外表头不会写回板块配置。
- 每条唯一聊天截图仍只生成一条记录。
- 导出只使用任务绑定版本的列定义，新增或删除普通字段可以通过版本配置生效。

### 回归

- 未成交分析专用执行器和接待质检专用执行器测试通过。
- 普通 AI 字段默认 `imageEnabled = false`，显式开启后才向模型请求发送图片。
- 相关权限、审计、上传安全、资源清理和历史版本测试通过。
