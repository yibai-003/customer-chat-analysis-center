# 接待质检 V2 规则覆盖与证据链规格

**状态：** 待用户审核  
**关联 Issue：** [#21 加固接待质检规则覆盖与证据链](https://github.com/yibai-003/customer-chat-analysis-center/issues/21)

## 目标

为新建接待质检任务发布一个向后兼容的新协议版本，确保模型检查完整规则目录、知识上下文不会被截断成损坏内容，且缺少后台凭证时不会将规则判定成确定合规或违规。

## 当前根因

- 严格质检提示词通过截图事实的 `sceneHints` 预先过滤售前或售后规则，视觉阶段漏判场景会让另一类规则不进入质检模型上下文。
- 知识快照超过 20,000 字符时按字符串切片，可能留下不完整 JSON 或半条知识记录；截断情况当前不会可靠地把质检结果转为人工复核。
- 现有证据 Schema 只接受截图对话编号；接待导入契约没有后台登记、备注、补发、退款等凭证列，但部分规则依赖这些后台证据。

## 方案

1. V2 质检提示始终包含任务绑定版本的完整规则目录；最终场景仍由质检阶段根据完整事实判定，不由视觉 `sceneHints` 预先排除规则。
2. V2 为每条场景适用规则返回明确判定状态。违规项继续要求可回溯的聊天原文、证据说明和理由；辅助字段引用只能指向该任务版本允许的字段，并校验原始值。
3. 每条业务规则明确声明其需要的证据来源。截图对话、配置版本知识快照和辅助字段可作为受限来源；当前未提供的后台记录来源标记为不可用。对依赖该来源的规则，运行时不得接受“合规”或“违规”为确定结论，必须记录缺失原因并转入人工复核。
4. 知识快照按完整知识库/条目边界纳入上下文，输出始终为合法 JSON。若因上下文预算未能纳入相关条目，则记录上下文不完整并要求人工复核；不得把半条知识作为模型依据。
5. 使用新增、不可变的接待配置版本启用 V2。当前数据库 schema 为 29，本功能以 append-only migration 030 从当前发布版本创建下一接待配置版本；已绑定的严格旧版本和 legacy 版本继续使用各自既有提示词、解析和派生行为，不重算历史结果。
6. 扣分、维度、D 级、等级、标签和建议仍只从任务绑定版本的本地业务规则派生。

## 非目标

- 不新增工作簿中的后台凭证列，也不改变接待导入/导出模板。
- 不提高并发、不更换模型、不以删减规则或提示词缩短耗时；性能工作由 Issue #4 跟踪。
- 不修改已发布配置快照或已完成分析结果。

## 验收标准

- [ ] V2 提示不根据 `sceneHints` 过滤规则；售前/售后/混合/无法判断均有规则覆盖回归测试。
- [ ] 每条适用规则有明确状态且覆盖完整；未知 ID、重复 ID、无效来源和伪造证据被拒绝或进入待复核。
- [ ] 不存在后台凭证列时，依赖后台凭证的规则不会产生确定合规/违规结果，并自动要求人工复核。
- [ ] 知识上下文超预算时只省略完整条目，JSON 仍可解析；影响判定的省略会自动要求人工复核。
- [ ] 新任务绑定新协议版本；旧版本的重试继续使用原版本提示词、规则和协议。
- [ ] 扣分、等级、标签和建议继续由本地版本规则派生。
- [ ] 接待质检单元、配置版本、迁移和 XLSX 端到端门禁通过。
