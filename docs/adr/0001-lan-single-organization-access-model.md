# ADR-0001：局域网版采用单组织共享数据与角色授权

**日期：** 2026-09-17  
**状态：** 已采纳

## 背景

客服解析中心将从本机单人使用升级为局域网多人使用。当前所有任务、记录、板块、知识库、模型配置和运行日志均是全局数据，尚无用户身份、权限或审计边界。

系统第一期仅服务一个内部组织。用户确认由管理员创建账号，不开放自助注册，并要求将审核人员与操作人员分离。

## 决策

局域网第一期采用以下访问模型：

1. 系统只有一个组织，组织内业务数据默认共享可见，不实施客户或部门间租户隔离。
2. 每个请求以已登录用户身份执行；创建者和操作者信息写入任务、导入、复核、导出、配置变更和管理操作的审计记录。
3. 采用五个角色：管理员、配置人员、操作人员、审核人员、只读人员。
4. 权限在服务端路由和服务边界强制校验，前端仅据此呈现可操作入口，不能作为授权依据。
5. 数据表及服务契约预留组织归属字段，但首期仅初始化一个组织。未来引入多组织时，必须在所有数据读取和写入路径实施组织过滤，不能只增加登录界面。

## 后果

### 正向

- 满足内部多人协作、职责分离和操作追溯。
- 首期不引入多租户管理、跨组织数据隔离和复杂的组织邀请流程。
- 为后续 SSO、部门隔离或客户租户化保留数据边界。

### 代价

- 认证和授权需要覆盖全部现有写入和敏感读取路径，不能只保护新增功能。
- 首期所有已授权用户仍能读取组织共享任务和记录；不提供按个人私有任务隔离。
- 从 SQLite 单实例迁移到服务型数据库时，需要保持本 ADR 的用户、组织和审计语义。

## 不采用的方案

- **只新增登录页：** 无法阻止直接调用现有 API，不能满足权限控制。
- **首期直接多租户：** 当前使用场景为单组织，提前实现会扩大数据迁移、管理和测试范围。
- **仅按创建者隔离任务：** 与“组织共享数据”的协作要求不一致，并会妨碍审核和管理流程。
