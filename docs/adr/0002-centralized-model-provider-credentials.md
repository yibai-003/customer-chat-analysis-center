# ADR-0002：模型供应商凭据集中保存在运行主机

**日期：** 2026-09-18  
**状态：** 已采纳

## 背景

客服解析中心的局域网版本由一台固定运行主机提供应用、数据和任务调度，多台组织内工作站通过浏览器共同使用。

模型供应商 API Key 属于组织级敏感配置。如果由每台工作站分别保存或在跨机验收时临时传入，会扩大凭据暴露范围，造成配置漂移，并使模型用量、故障切换和审计难以统一。

## 决策

1. 模型供应商及其 API Key 由管理员在固定运行主机上统一配置和保存。
2. 普通工作站和跨机正式验收不得持有或传入模型 API Key，只能引用主机上已审批的供应商。
3. 模型配置、模型池、配额、能力检测、调用用量和故障切换由运行主机统一管理。
4. 工作站只负责上传任务、发起解析、查看结果、复核和导出；模型请求由运行主机发出。
5. 桩模型和隔离预演允许使用临时 Key，但证据必须标记为预演，不能用于正式签收。
6. 当前正式签收范围只覆盖外部 HTTPS 模型供应商。若未来在主电脑或独立 GPU 节点部署本地推理服务，需要单独设计健康检查、资源隔离、重启恢复和本地端点可信证明。

## 后果

### 正向

- API Key 不进入普通工作站、命令历史和跨机验收文件。
- 所有用户共享一致的供应商、模型池和配额策略。
- 模型调用、用量和失败切换集中审计。
- 后续把推理迁移到独立服务时，工作站流程无需变化。

### 代价

- 运行主机是模型调用的统一出口，网络或主机故障会影响全部用户。
- 管理员必须在正式跨机验收前完成供应商配置和能力检测。
- 本地推理不是本 ADR 的自动延伸，需要新的容量和运维设计。

## 工单拆分

- 本次调整属于 Issue 11 的主机安全边界和 Issue 12 的真实模型闭环修正，不新增工单。
- 只有确定建设“主电脑本地模型”或“独立局域网 GPU 推理节点”时，才新增本地推理部署与验收工单。

## 不采用的方案

- **每台工作站分别保存 API Key：** 暴露面大，配置和用量无法统一。
- **跨机验收临时传入真实 Key：** 密钥会进入工作站环境或命令历史，不符合集中管理边界。
- **把任意私网模型地址直接视为真实供应商：** 无法区分正式推理服务和桩服务，也缺少资源与恢复证明。
