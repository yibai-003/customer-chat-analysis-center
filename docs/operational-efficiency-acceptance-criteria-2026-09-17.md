# 模型池、批量选择与解析效能验收标准

**日期：** 2026-09-17  
**关联实施：** [实施计划](operational-efficiency-implementation-plan-2026-09-17.md)  
**状态：** 待验收

## 目的

定义模型池验证与剔除、记录多选定向解析、板块速度和 AI 字段合理性校验的可执行验收口径。验收以实际接口响应、数据库事实数据和用户可见行为为准，不以代码存在或页面截图替代。

## 验收准备

1. 建立一个至少包含两个板块、每个板块至少三个字段的测试任务；其中至少一个字段实际调用 AI，至少一个字段不调用 AI。
2. 准备至少 30 条记录，覆盖 `pending`、`completed`、`failed`、`needs_review` 和不可执行状态；至少 12 条记录跨两页展示。
3. 准备至少三个模型池成员，覆盖已验证可用、验证失败/过期、已剔除；保留一条可模拟限流、网络失败或验证失败的测试路径。
4. 写入或执行足够的字段运行和模型使用事件，覆盖成功、失败、待复核、模型切换、缓存命中或跳过、缺失耗时/令牌等情况。
5. 验收环境不得使用真实生产密钥进行破坏性测试；验证与解析预算必须受既有预算和取消机制约束。

## 一、模型池验证与剔除

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| MP-01 | 选中验证 | 选择两个在池模型并执行“验证已选” | 只请求并更新这两个成员；每个成员显示独立通过/失败结果、验证时间和错误摘要。 |
| MP-02 | 部分失败 | 一个模型通过、一个模型返回认证或模型不存在错误 | 通过项正常更新，失败项保留在表中并标为失败；操作不因单项失败而整体丢失结果。 |
| MP-03 | 通过后启用 | 对已剔除模型勾选“通过后启用”并验证成功 | 模型恢复为可入池状态；未勾选时验证成功不得自动改变其入池状态。 |
| MP-04 | 验证失败保护 | 对在池模型执行验证并失败 | 仅更新能力/健康状态；模型不会因一次失败被自动剔除。 |
| MP-05 | 批量剔除 | 选择多个在池模型，填写原因并确认剔除 | 所选模型不再参与对应用途路由；配置、供应商关联、历史运行和使用事件仍可查询。 |
| MP-06 | 最后可用模型 | 剔除一个用途的最后可用成员 | 界面明确提示用途将未就绪；系统不得静默改用付费模型或其他用途模型。 |
| MP-07 | 恢复入池 | 恢复一条已剔除成员 | 成员回到待验证/按验证状态待路由状态；旧的过期或失败验证不能直接作为可用依据。 |
| MP-08 | 选择边界 | 提交空列表、重复 ID、非池成员 ID、超过 50 个 ID | 服务端返回明确 4xx 错误；不改变任何未校验成员状态。 |
| MP-09 | 视图一致性 | 验证、剔除和恢复后刷新页面 | 表格、汇总、用途就绪状态和操作可用性一致；不会显示陈旧的“已验证可用”。 |

通过条件：

- 所有 MP 场景通过。
- 路由候选列表中不出现已剔除成员。
- 验证、剔除、恢复动作均有用户可读的成功/失败反馈。
- 不存在通过前端构造请求即可修改其他池成员或未选成员的情况。

## 二、记录多选与定向批量解析

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| RS-01 | 单条选择 | 勾选一条记录 | 工具栏显示“已选择 1 条”；点击复选框不打开记录详情。 |
| RS-02 | 全选本页 | 点击“全选本页” | 仅当前页符合当前筛选条件的记录被选中，计数准确。 |
| RS-03 | 跨页保留 | 首页选择 3 条，切到第二页再选择 2 条并返回 | 已选总数为 5，首页原选择仍可见。 |
| RS-04 | 上下文隔离 | 已选择后切换任务、板块或筛选条件 | 选择被清空，不能把旧上下文 ID 带入新任务或板块。 |
| RS-05 | 定向启动 | 选择 5 条记录并点击“解析已选”，确认对话框 | 对话框显示 5 条；发出的批量请求包含去重后的 5 个 `recordIds`。 |
| RS-06 | 精确执行 | 在选中记录外保留多条可执行记录 | 本次运行只产生选中记录的字段运行；未选记录的状态、运行数和更新时间不变。 |
| RS-07 | 全量回归 | 未使用“解析已选”，执行原“批量解析” | 保持现有全量/既有范围行为，不受选择状态影响。 |
| RS-08 | 非法 ID 防护 | 向接口提交空列表、重复 ID、其他任务的 ID 或超过上限的 ID | 服务端拒绝请求且不启动任务；无跨任务记录被处理。 |
| RS-09 | 状态跳过 | 选择包含不可执行状态的记录 | 页面或任务结果明确显示选中数、可执行数和跳过数；不可执行记录不会被错误改写。 |
| RS-10 | 启动失败 | 模拟网络错误、容量检查失败或任务锁冲突 | 选择仍保留，用户可重试；不会回退为全量解析。 |
| RS-11 | 无障碍与布局 | 键盘操作复选框，在桌面和窄屏检查工具栏 | Space/Enter 可改变选择；焦点可见；计数、按钮和分页不重叠或截断。 |

通过条件：

- 所有 RS 场景通过。
- 服务端记录的实际处理 ID 集合与确认时选中的去重 ID 集合一致。
- 原有暂停、取消、重试、模型预算和任务锁仍对定向任务生效。

## 三、板块速度与 AI 字段合理性校验

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| PM-01 | 时间范围 | 选择默认最近 30 天和自定义时间范围 | 板块概览、字段明细和模型使用明细均随范围变化，显示当前样本数与覆盖率。 |
| PM-02 | 速度计算 | 准备已知耗时样本 | 平均值、P50、P95 与服务端测试中的预期值一致；P95 不在样本不足时伪造。 |
| PM-03 | 字段状态 | 准备成功、失败、待复核、跳过运行 | 每个字段正确显示调用数、成功率、失败率、待复核率和跳过数；分类基于事实运行而非是否启用。 |
| PM-04 | AI 调用识别 | 比较 AI 字段和非 AI 字段 | AI 使用指标只归因于实际模型路由字段；非 AI 字段不被计入模型令牌、模型分布或异常重试。 |
| PM-05 | 模型使用 | 准备多模型、切换、冷却、额度和令牌事件 | 页面显示模型分布、请求数、切换/异常事件、输入/输出令牌及缺失率；可追溯到原始事件。 |
| PM-06 | 慢字段提示 | 使满足最小样本量的字段 P95 超过已配置阈值 | 字段标为“关注”，并显示“P95 超阈值”的具体数值和阈值。 |
| PM-07 | 稳定性提示 | 使失败率、待复核率或平均模型请求数超过阈值 | 字段标为“关注”，每项命中规则独立展示，不能以单一笼统错误替代。 |
| PM-08 | 样本不足 | 字段样本少于最小样本量 | 标为“样本不足”，展示原始样本和耗时；不得输出“慢”“稳定”结论。 |
| PM-09 | 历史缺失数据 | 使用没有耗时、令牌或字段关联的历史运行 | 页面显示可用数据比例与缺失说明；不将缺失值当作 0，也不阻断其他可用统计。 |
| PM-10 | 只读保障 | 打开、筛选、排序和刷新效能检查 | 不产生模型调用、字段运行、模型池配置变更或记录状态变更。 |
| PM-11 | 空态与权限 | 选择无运行数据板块或无效时间范围 | 显示明确空态或输入错误；不会显示上一次板块的残留统计。 |

通过条件：

- 所有 PM 场景通过。
- 指标的原始聚合查询、阈值分类和分位数计算均有独立自动化测试。
- “合理性”只产生提示，不会自动禁用 AI 字段、剔除模型、改变预算或重跑记录。

## 四、数据完整性与回归

1. 所有数据库结构变化均通过新增迁移完成；已冻结迁移未被修改，`npm run db:check` 通过。
2. 模型剔除后，历史 `analysis_runs`、`analysis_field_runs` 和 `model_usage_events` 仍可按原 ID 查询。
3. 定向解析的请求 ID、任务归属和执行 ID 在服务端测试中逐项断言；不接受依赖浏览器隐藏按钮的安全保障。
4. 指标聚合在空数据、缺失数据、重复事件、跨任务记录、缓存命中和取消运行下均有确定结果。
5. 交付前依次通过：

```text
npm test
npm run typecheck
npm run lint
npm run build
npm run db:check
npm run smoke
npm run check:installation
```

6. Markdown 索引和两份文档的相互链接检查通过。

## 回退

验收不通过时，按实施计划的回退策略关闭对应新入口：模型池保留配置并恢复入池状态，定向解析隐藏“解析已选”入口并继续使用既有全量批量流程，效能检查下线只读入口和聚合 API。不得删除历史运行、模型使用事件或通过修改冻结迁移回退。
