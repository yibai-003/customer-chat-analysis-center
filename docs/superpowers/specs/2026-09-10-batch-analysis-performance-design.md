# 批量解析性能整改设计

## 目标

让包含数千条截图记录的任务能够持续在后台解析，同时保持网页可操作，避免一次加载全部记录、全部缩略图以及高频数据库写入造成明显卡顿。

## 当前问题

1. `GET /api/jobs/:id/records` 返回任务的全部记录，前端同时渲染全部行和缩略图。
2. 批量解析启动后，服务端将全部记录放入同一轮并发执行，直到任务结束才退出。
3. 每完成一条记录都会同步写入任务进度，数千条数据会产生大量 SQLite 写操作。
4. 前端每 700 毫秒轮询任务状态，任务结束后再次全量刷新记录。

## 设计方案

### 记录分页

记录列表接口支持以下参数：

- `page`：页码，默认 1。
- `pageSize`：每页数量，默认 50，最大 200。
- `status`：按解析状态或复核状态筛选。

接口返回：

```ts
{
  items: RecordSummary[];
  total: number;
  page: number;
  pageSize: number;
}
```

前端只渲染当前页。筛选、切换任务和解析状态变化时重新请求当前页，不再把全部记录保存在浏览器内存中。

### 后台分批解析

批量任务按以下方式执行：

1. 每次从数据库取最多 `ANALYSIS_BATCH_SIZE` 条待处理记录，默认 20。
2. 批次内部继续使用 `ANALYSIS_CONCURRENCY` 控制 AI 并发，默认 2。
3. 每批结束后统一更新任务进度，并释放事件循环。
4. 任务仍在运行时继续获取下一批，直到没有待处理记录。
5. 每批开始前和每条记录开始前检查暂停、取消状态。

服务端不再为一次任务长期持有全部记录数组。继续解析已暂停任务时，只处理仍为待解析、失败或需复核且符合本次运行范围的记录。

### 进度和前端交互

- 批量解析接口仍立即返回，不等待任务完成。
- 前端轮询间隔调整为 2 秒。
- 轮询只请求任务概要；当前页记录按较低频率或批次进度变化刷新。
- 启动解析后解除全局页面 `busy`，仅锁定冲突操作。
- 暂停、取消、失败重试和单条解析保持现有入口。

### 本机性能检测和运行建议

新增 `GET /api/system/analysis-capacity`，实时读取：

- CPU 逻辑处理器数量。
- 总物理内存和当前可用内存。
- `DATA_DIR` 所在磁盘的可用空间。
- 当前正在解析任务数量。

接口返回用于计算本机能够稳定承担的本地处理上限。模型接口的 RPM、TPM 和供应商并发限制无法从本机检测，因此页面推荐值仍采用保守上限。

推荐规则：

1. CPU 建议并发为逻辑处理器数量除以 4，最高不超过 4。
2. 可用内存低于 3 GB 时，并发限制为 1；3-6 GB 为 2；6-12 GB 为 3；12 GB 以上为 4。
3. 最终建议并发取 CPU 建议、内存建议和最大值 4 中的最小值。
4. 建议批次大小为建议并发的 10 倍，限制在 10-40 条。
5. `DATA_DIR` 可用空间低于 10 GB 时显示容量警告，但磁盘空间不直接提高并发。
6. 已有其他解析任务运行时，建议并发进一步按运行任务数均分，最低为 1。

按当前机器实时状态（20 个逻辑处理器、15.84 GB 总内存、2.42 GB 可用内存），建议 AI 并发为 1、批次大小为 10。该值会随空闲内存和正在运行的任务数量动态变化。

点击“批量解析”后先打开运行设置弹窗，显示检测结果、推荐并发和推荐批次。用户可以：

- 直接使用推荐值启动。
- 在安全范围内手动调整并发和批次。
- 看到高于推荐值时的负载警告。

本次选择随启动请求提交，只作用于当前任务运行，不修改环境变量，也不需要重启服务。暂停后继续解析时沿用该任务最近一次的运行参数。

### 数据库

- 为 `records(job_id, status, row_number)` 增加索引，支持批次查询和状态筛选。
- 为 `records(job_id, review_status, row_number)` 增加索引。
- 任务总进度根据当前运行累计值更新，不在每条记录完成后重复读取完整任务。

## 配置

新增：

```env
ANALYSIS_BATCH_SIZE=20
```

保留：

```env
ANALYSIS_CONCURRENCY=2
```

批次大小控制数据库和调度负载，并发数控制同时发出的模型请求。二者职责分离。环境变量作为未传入任务参数时的后备值；网页启动任务时优先使用本次选择的参数。

## 错误处理

- 单条记录失败不会停止当前批次。
- 批次异常时任务进入失败状态并释放运行锁。
- 暂停只阻止新记录开始；正在请求模型的记录完成后退出。
- 取消与暂停相同，但任务最终状态为已取消。
- 页面请求失败显示统一风格提示，不清空已经加载的当前页。

## 测试

1. 分页接口正确返回页数、总数和状态筛选结果。
2. 批次调度单次不超过配置数量，并处理完全部记录。
3. 批次之间检查暂停和取消。
4. 任务进度按批次写入，最终计数正确。
5. 前端分页切换、状态筛选和解析轮询组件测试。
6. 性能检测接口能够根据 CPU、可用内存、磁盘和运行任务数生成稳定建议。
7. 启动弹窗默认使用推荐值，并对超过推荐值的输入显示警告。
8. 现有单条解析、失败重试、知识库解析和导出测试保持通过。

## 非目标

- 本阶段不引入 Redis、RabbitMQ 或独立 Worker 服务。
- 本阶段不实现多用户任务隔离。
- 本阶段不改变模型接口和字段解析链。
- 本阶段不对导出流程做流式重写。
