# 免费模型池设计

## 目标

为客服解析中心建立统一的多模态与文本模型池。系统优先消耗千问平台账户中的免费额度，按到期时间自动接力；免费额度不可用后，才允许使用付费兜底模型。

现有单模型配置继续可用。改造后，API Key 与模型成员分离，同一千问凭证无需为每个模型重复保存。

## 架构

### 模型服务商

新增模型服务商概念，用于保存：

- 服务商名称。
- OpenAI 兼容 Base URL。
- 加密后的 API Key。
- 启用状态。

迁移时，将现有千问视觉和文本配置合并到一个千问服务商。模型配置通过 `provider_id` 引用服务商。旧配置仍保留原有 Base URL 和密文列作为兼容数据，调用时优先读取服务商凭证。

### 模型成员

沿用 `model_configs` 作为可调用模型成员，并增加：

- `provider_id`：服务商。
- `pool_enabled`：是否参与自动调度。
- `billing_mode`：`free` 或 `paid`。
- `quality_tier`：`A`、`B`、`C`。
- `priority`：同条件下的人工顺序。
- `thinking_mode`：是否为思考模型。
- `quota_total_tokens`：免费额度总量。
- `quota_used_tokens`：本地累计用量。
- `quota_expires_at`：到期时间。
- `quota_safety_ratio`：默认 `0.95`。
- `cooldown_until`：限流或临时故障冷却时间。
- `consecutive_failures`：连续失败次数。
- `last_success_at` 和 `last_failure_at`。

视觉与文本仍由现有 `purpose` 区分，因此第一版不新增可任意创建的池实体，避免引入当前不需要的多池复杂度。

### 使用事件

新增 `model_usage_events`，记录：

- 模型成员。
- 调用用途。
- 成功、失败、切换、额度耗尽或冷却事件。
- 输入与输出 Token。
- 错误分类。
- 关联记录和字段。
- 调用时间。

该表用于额度统计、故障排查和配置界面的调用记录，不保存 API Key。

## 调度规则

候选成员必须同时满足：

- 已启用。
- 参与模型池。
- 用途匹配。
- 不在冷却期。
- 能力检测通过且结果未过期；新安装成员在首次能力检测前不可承接正式批次。
- 免费成员未到期，且本地使用量低于 `总额度 × 安全比例`。

排序顺序：

1. 免费成员优先于付费成员。
2. 免费成员按到期时间升序。
3. 同一到期时间按剩余额度升序，优先用完较小余额。
4. 按质量等级 A、B、C。
5. 非思考模型优先于思考模型。
6. 按人工优先级。
7. 按近期成功率和最近成功时间。

Thinking 成员只有在当前记录的非 Thinking 免费成员全部失败或不可用时才参与候选。

## 错误与接力

- 明确额度不足、余额不足或免费额度耗尽：标记该成员额度耗尽，立即切换。
- HTTP 429：进入冷却，首次 60 秒，连续触发时指数增加，最大 30 分钟。
- HTTP 408、网络超时或 5xx：当前成员最多重试一次，之后进入短期冷却并切换。
- HTTP 401/403：停用该服务商凭证并阻止继续调用，避免所有成员重复失败。
- HTTP 400、404 或模型不存在：停用该模型成员，不影响同服务商其他成员。
- 输出格式错误：本地修复一次；不能修复时，同一成员重试一次，之后切换。
- 内容证据不足：不视为模型故障，不切换模型，结果进入需复核。
- 用户取消、任务预算耗尽或系统磁盘错误：立即停止，不进行接力。

一次成功返回后不得继续调用其他模型。同一截图只有当前模型明确失败且没有可用结果时才能由下一多模态成员重新解析。

## 用量与费用保护

- 每次成功调用以供应商返回的 `prompt_tokens` 和 `completion_tokens` 更新本地额度。
- 缺少 usage 时记录未知用量并告警，不以估算值扣减正式余额。
- 免费成员达到 95% 本地额度后停止调度。
- 付费成员需要显式标记为付费兜底。
- 支持单批次最大付费 Token、每日最大付费 Token 和每月最大付费 Token。
- 默认付费预算为 0；未配置预算时，免费池耗尽后任务进入“等待额度/需处理”，不得静默计费。

## 配置界面

现有单一表单调整为三个视图：

### 服务商凭证

- 展示服务商、Base URL、Key 掩码和状态。
- 更新一次 Key 即影响其全部模型成员。
- 支持连接测试。

### 模型池

- 使用“多模态”和“文本”标签页。
- 每行展示模型、等级、免费/付费、总额度、已用、剩余、到期时间、冷却和能力状态。
- 支持启用、停用、调整等级和人工优先级。
- 提供“安装/更新千问免费池”命令。
- 更新预设时按模型 ID 幂等写入，不覆盖人工停用、能力检测结果和实际用量。

### 调用状态

- 展示最近模型切换、失败原因、Token 使用和付费兜底情况。
- 支持按用途、模型和状态过滤。

界面不展示或返回完整 API Key。

## 安装与更新

“安装/更新千问免费池”执行：

1. 找到当前启用的千问服务商；不存在时提示先配置凭证。
2. 使用项目内置的、带版本号的免费池预设。
3. 创建不存在的模型成员。
4. 更新预设维护的等级、额度和到期时间。
5. 保留本地使用量、人工启停、能力检测和冷却状态。
6. 对新增成员执行能力检测；检测失败的成员保持不可调度。

第一版不登录或抓取千问权益网页，也不自动修改平台的“免费额度用尽即停”开关。

## 调用入口

新增统一模型路由服务，替代各业务服务自行遍历模型：

- 字段分析。
- 统一接待流程质检。
- 高频问答提炼。
- 知识库匹配与抽取。
- 未成交分析。

路由服务返回实际使用的模型快照、Token、尝试记录和最终响应。业务服务只负责构造提示词与验证业务结果。

## 兼容与迁移

- 旧模型配置自动关联到迁移生成的服务商。
- 旧默认模型继续作为付费兜底或独立备用，不会被删除。
- 现有 API 暂时保留；新增服务商、预设安装、池状态和事件查询 API。
- 现有分析运行中的模型快照格式继续可读，并增加池选择信息。
- 数据库迁移前沿用现有自动备份和完整性检查。

## 验证

至少覆盖：

- 服务商迁移不会暴露或损坏 API Key。
- 千问免费池预设幂等安装。
- 到期时间、剩余额度、等级和 Thinking 排序。
- 达到 95% 后自动跳过。
- 429、5xx、额度耗尽、鉴权失败和格式错误的接力行为。
- 成功后不重复调用下一模型。
- 同一截图只在明确失败时重新解析。
- 付费预算为 0 时不会产生付费调用。
- 模型池 UI 的安装、编辑、状态和错误展示。
- 现有字段分析、知识库和质检回归测试继续通过。

## 非目标

- 自动抓取千问权益网页。
- 自动创建或修改千问平台 API Key。
- 自动操作平台“免费额度用尽即停”开关。
- 第一版实现 OCR 与视觉模型的双阶段组合调用。
- 根据模型排行榜自动调整质量等级。
