# 百炼千问按量模型池设计

**日期：** 2026-10-12

**状态：** 已获需求确认，实施前规格

**关联工单：** [GitHub Issue #16](https://github.com/yibai-003/customer-chat-analysis-center/issues/16)

## 1. 目标

保留当前已经配置的基础模型、默认模型和服务商凭据，从百炼模型目录中识别满足客服解析所需能力的千问模型，加入模型池并按量计费。模型是否免费、是否有剩余额度、免费额度是否到期不参与准入判断。

同步只负责发现和维护模型配置。新发现的千问模型默认不进入路由，管理员仍需使用现有能力验证并显式启用；真正的付费使用受现有批次 Token 预算和模型池付费预算控制。

## 2. 范围与不变项

### 包含

- 使用百炼模型目录快照，不调用免费额度或用量接口。
- 只纳入模型 ID 以 `qwen` 开头、且满足当前文本/视觉/结构化输出能力条件的模型。
- 同一个精确模型 ID 只产生一个用途成员；支持图片输入的模型归入视觉池，否则归入文本池。
- 新增和受管千问成员使用 `billing_mode='paid'`，不写入免费额度总量、已用量或到期时间。
- 预览、过期校验、池指纹和 SQLite 单事务应用继续保留。
- 已有静态千问成员或旧百炼托管成员迁移时保留 ID、能力验证、冷却/失败诊断、人工剔除、使用事件和管理员排序；仅切换为按量托管标记。
- 非千问的旧托管成员不再进入新千问池；应用后停用但保留行和历史，不能删除。

### 不包含

- 查询或展示免费状态、免费额度、剩余额度、额度有效期、`autoStop` 或 95% 免费安全线。
- 修改基础模型、`is_purpose_default`、默认模型顺序、分析历史、每日/月度付费预算或服务商 API Key/Base URL。
- 自动开启云端按量/免费开关。
- 自动调用模型验证、自动启用模型、网页直接访问主机 CLI 或驻留代理。

## 3. 数据流

```text
百炼 CLI 模型目录（不含额度查询）
        ↓ 规范化目录快照
主机脚本 → 项目登录会话 → 服务端预览 → 管理员确认 → SQLite 单事务应用
                                      ↓
                    千问模型配置（paid、未入池、待验证）
```

主机脚本可以继续通过百炼 CLI 获取完整目录，但只执行只读模型目录命令。脚本把目录字段规范化后发送到服务端，不发送 CLI 凭据、Cookie、API Key 或原始控制台输出。若目录响应无法证明完整、存在重复模型 ID、字段缺失或超过上限，预览请求直接失败且不写库。

## 4. 候选条件

服务端策略函数接收 `{ providerId, capturedAt, accountMatchConfirmed, models }` 快照：

1. `model` 必须是安全的精确模型 ID，并以 `qwen`（不区分大小写）开头；其他目录模型进入排除摘要，不创建或更新千问成员。
2. 文本候选必须声明文本输入、文本输出和结构化 JSON 输出能力。
3. 视觉候选必须声明图片输入、文本输出和结构化 JSON 输出能力；多模态模型按视觉候选处理。
4. `offline=true`、当前已下线、能力字段缺失、结构化输出未声明或目录同 ID 重复的模型被排除。
5. 目录中的未来下线时间只用于信息展示和同步时的可用性判断，不作为免费额度条件；模型在当前时刻仍可用即可进入预览。
6. 服务器端再次执行 Qwen 过滤，不能只信任主机脚本已经过滤过的结果。

候选不包含 `quotaTotalTokens`、`quotaUsedTokens`、`quotaExpiresAt` 等免费额度字段；数据库中的这些可选字段对按量千问成员保持 `NULL`/零默认值，不参与路由准入。

## 5. 数据库与路由行为

- 新成员写入已有 `model_configs` 表，`billing_mode='paid'`、`is_purpose_default=0`、`is_enabled=1`、`pool_enabled=0`，并使用新的 Qwen 托管 `preset_key`/版本标记。
- 应用时使用选定的已启用百炼 provider 的现有 `base_url` 和加密 API Key；同步不创建、删除、启停或改写 provider 行。
- 旧 `qianwen-free-pool`、`bailian-free-pool` 托管行在能精确匹配时原地迁移到新标记并切换为 paid；保留管理员调整过的优先级和人工剔除状态。
- 基础模型和任何非托管手工模型不被同步覆盖。若同一 provider、用途和模型 ID 已由手工配置占用，预览失败并要求管理员处理，不自动接管。
- 缺失或不再符合能力条件的旧千问托管行只设置 `pool_enabled=0` 并保留数据、历史和失败原因。
- 现有服务端排序继续将 `is_purpose_default=1` 的付费基础模型置于托管成员之后；付费模型能否路由由当前批次 Token 预算和模型池策略决定。

## 6. 服务商与安全边界

预览必须指定一个已启用且地址属于百炼的 provider。多 provider 时不猜选；脚本要求操作者确认 CLI 账号和所选 provider 属于同一百炼账户，但系统不宣称能够从两个凭据中机器验证该关系。服务商配置字段、凭据密文和审计脱敏规则沿用 ADR-0002，不把账号、Key、Cookie 或完整目录原文写入日志。

预览继续使用短期随机 ID、操作者绑定和模型池指纹；过期、操作者不一致、provider 被停用、池状态变化或事务失败时拒绝应用并保持零数据库修改。

## 7. 接口与界面

路由可沿用当前动态同步 API 的结构，但请求/响应名称和用户文案必须改为“百炼千问模型目录/按量模型池”，不得继续提示“安装/更新千问免费池”。主机命令入口改为清晰的 Qwen/paid 名称；客户端不直接调用 CLI。

同步预览显示新增、更新、停用、排除数量和精确模型 ID。新成员行显示“按量计费 / 待验证”，而不是免费额度进度条。付费默认模型继续固定置底。

## 8. 测试验收

- 纯函数测试覆盖 Qwen 前缀过滤、文本/视觉能力、结构化输出、离线/缺字段/重复目录和未来下线边界；明确没有免费额度字段或免费状态调用。
- 服务测试覆盖新增 paid 未入池、重复同步幂等、旧免费托管行迁移、非 Qwen 旧行停用、手工模型冲突、基础模型和 provider 字段不变、事务回滚和预览过期。
- PowerShell 测试只验证模型目录 JSON 解析、完整性和敏感字段不外传；测试中不得调用免费额度命令。
- 路由/UI 测试覆盖权限、审计脱敏、按量文案、默认模型置底和旧免费安装入口不再出现。
- 不对真实 LAN 数据库或真实百炼账户执行 apply；仅运行隔离测试和静态检查。
