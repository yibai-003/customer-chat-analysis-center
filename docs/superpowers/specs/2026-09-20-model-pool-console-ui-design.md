# 模型池控制台 UI 优化设计

**日期：** 2026-09-20

**关联工单：** `.scratch/model-pool-optimization/issues/02-model-pool-console-ui.md`

## 目标

在不修改模型池 API、排序和权限行为的前提下，提高模型身份、选中状态和额度信息的扫描效率，并为异常额度数据提供稳定展示。

真实局域网多分辨率截图属于后续验收，不在本次自动实现的完成条件内。

## 现有基础

- `PoolView.tsx` 已包含用途切换、批量选择、验证、剔除、恢复和行内编辑。
- 模型池表格使用固定布局和横向滚动。
- 现有测试通过 `ModelConfigDialog.test.tsx` 覆盖模型池请求和批量行为。
- `ModelConfig` 已提供供应商、额度、计费模式、阻断和状态字段。

## 设计

### 1. 模型身份列

模型身份列固定包含：

- 模型显示名：最多两行，稳定行高；
- 原始模型 ID：等宽字体，单行省略；
- 服务商名称：辅助文本，单行省略。

列宽使用固定的最小和最大约束。长文本不能改变表格列宽或造成逐字断行。

### 2. 原生语义复选框

保留 `input[type="checkbox"]`，通过 CSS定制方形外观：

- 未选中、悬停、选中和禁用状态；
- `:focus-visible` 明确外轮廓；
- 全选框支持 `indeterminate`；
- 选中行使用低对比度浅绿色背景；
- 点击复选框只改变选择，不触发行内编辑。

全选状态由当前用途下可见成员计算：

- 无成员或无选中：未选中；
- 全部可见成员已选：选中；
- 部分可见成员已选：半选。

### 3. 额度展示模型

新增纯函数将运行时额度字段归一化为展示状态：

- `quotaTotalTokens == null`：`unlimited`，显示“不限额”；
- 总额为有效正数：计算 `used / total`，限制在 `0-100%`；
- 总额为 `0`、负数或非有限数：`invalid`，显示“额度数据异常”；
- 已用为负数或非有限数：按 `0` 参与比例计算，同时显示安全的格式化值；
- `quotaBlocked` 或已用达到/超过总额：`exhausted`；
- 达到 `quotaSafetyRatio`：`warning`；
- 其他情况：`normal`。

有限有效额度使用原生进度语义：

- `role="progressbar"`；
- `aria-valuemin="0"`；
- `aria-valuemax` 为总额；
- `aria-valuenow` 为归一化后的已用值；
- `aria-label` 包含模型名称和精确比例。

精确 Token 数值始终保留在进度条旁。

### 4. 状态视觉

- 正常额度：工作台绿色；
- 接近安全阈值：橙色；
- 耗尽或阻断：红色；
- 不限额：中性青绿色；
- 数据异常：中性警告样式，不伪装为可用或耗尽。

颜色之外必须同时显示文字，不能只依赖颜色表达状态。

### 5. 文件边界

- `PoolView.tsx`：组合表格、选择状态和额度展示。
- 新增独立额度展示模块：归一化额度数据并渲染进度语义。
- 新增独立复选框组件：封装原生 checkbox 和半选状态。
- `styles.css`：模型池专属尺寸、复选框、选中行和额度样式。
- 聚焦测试文件覆盖纯函数、ARIA语义和既有批量行为。

不引入新的 UI组件库，不改动服务端 API。

## 错误与边界

- 空模型池不渲染半选状态。
- 用途切换继续清空选择。
- `null`、`0`、负数、超额、`NaN` 和无穷值均不导致渲染异常。
- 编辑模式继续使用现有输入框，不用进度条替代可编辑额度字段。
- 批量验证、剔除、恢复和编辑请求结构保持不变。
