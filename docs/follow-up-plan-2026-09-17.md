# 后续推进计划

**日期：** 2026-09-17

## 当前结论

当前项目的基础业务已经在 `origin/main` 上可追踪，包含：

- Excel 聊天截图导入与解析；
- 知识库管理、检索和快照同步；
- 批量解析分页、暂停、取消和重试；
- Excel 导出；
- 备份恢复和数据库迁移；
- 上传、磁盘、密钥和本地访问安全控制；
- 健康检查、就绪检查和日志维护。

当前 `main` 相对 `origin/main` 领先的 3 个提交是：

1. 免费模型池设计文档；
2. 免费模型池实施计划；
3. 忽略本地 worktree 的 Git 配置。

本次推送尝试因无法连接 GitHub `443` 端口失败，网络恢复后需要重新执行：

```powershell
git push origin main
```

## 推进顺序

### 阶段一：恢复可验证环境

1. 不修改业务代码，执行 `npm ci`。
2. 重新执行全量测试、类型检查、构建和数据库检查。
3. 保存完整测试输出。
4. 若仍有失败，区分依赖问题、环境问题和业务断言问题。

完成标志：

- 全量测试可稳定启动；
- CLI 测试可以创建子进程；
- 数据库检查可以执行；
- 依赖版本与 `package-lock.json` 一致。

### 阶段二：完成未成交分析

1. 逐项处理 `docs/fix-plan-2026-09-17.md` 中的未成交分析问题。
2. 先补测试，再修改实现。
3. 验证调用次数、证据约束、知识库标准名称、公共字段派生和话术规则。
4. 执行真实 XLSX 导出回读。
5. 单独提交未成交分析相关代码和测试。

完成标志：

- 未成交分析专项测试通过；
- 兼容性测试通过；
- 进度记录可以标记完成；
- 未成交分析相关提交可单独审查。

### 阶段三：完成接待流程质检

1. 核对迁移 009 至 013 与当前 catalog。
2. 验证售前、售后、混合和无法判断四类场景。
3. 验证规则覆盖、证据编号、评分、等级、标签和人工复核状态。
4. 验证内部字段不进入导出文件。
5. 单独提交接待质检相关代码和测试。

完成标志：

- 接待质检专项测试通过；
- 数据库迁移和恢复测试通过；
- Excel 导出回读通过；
- 旧板块回归测试通过。

### 阶段四：推进免费模型池

免费模型池已经在独立 worktree `feat/model-pool` 中完成主要实现和多轮修复，但尚未合并到当前 `main`。

后续步骤：

1. 先完成主线未提交业务的拆分和收口。
2. 对 `feat/model-pool` 重新执行独立测试和类型检查。
3. 检查模型池分支是否携带了未成交分析、接待质检等基线代码。
4. 确认合并顺序，避免重复迁移或覆盖同一字段执行逻辑。
5. 合并后重新执行全量回归和就绪检查。

模型池合并前必须特别确认：

- 免费模型优先和付费预算为 0 的行为；
- 取消后的用量记账；
- 迁移生成的服务商和旧凭据兼容；
- 知识库匹配和热点问题捕获均走统一路由；
- 既有视觉和文本模型配置仍能读取。

### 阶段五：最终整理和推送

1. 检查 `git status`，确认没有未预期文件。
2. 按功能边界提交。
3. 在干净依赖环境中执行完整验证。
4. 推送 `main` 或按需要创建功能分支。
5. 记录远端提交哈希和验证结果。

## 暂不做的事项

在阶段一到阶段三完成前，暂不：

- 继续增加业务功能；
- 修改现有数据库数据；
- 重建知识库内容；
- 合并免费模型池分支；
- 强行拆分或提交当前未完成业务改动；
- 修改 `package-lock.json`；
- 绕过 GitHub 网络或证书校验问题。
