# 模型池、批量选择与解析效能实施计划

**日期：** 2026-09-17  
**状态：** A、B 已实施并推送（`fc5e959`）；C 经用户决定取消（2026-09-17）  
**关联验收：** [验收标准](operational-efficiency-acceptance-criteria-2026-09-17.md)

## 目的

解决日常使用中的三项操作缺口：

1. 模型池缺少面向已入池模型的批量验证、明确剔除和恢复入口。
2. 记录列表虽有单条勾选框，但选中状态未接入批量解析，用户无法直接对多条记录发起定向解析。
3. 缺少按解析板块观察速度、失败和复核情况的视图，也无法判断启用的 AI 字段是否实际产生合理的模型消耗。

目标是降低人工逐条操作成本，并提供可解释、可回退的运行决策依据；不在本次范围内自动替换模型、自动禁用字段或修改已有解析结果。

## 现状与边界

- 模型池已保存能力验证状态、最近验证时间、连续失败数、冷却时间和模型使用事件；当前“验证默认模型”主要服务于免费模型池首启，缺少通用的按选中成员验证与剔除操作。
- 模型池现有编辑能力可修改 `poolEnabled` 与 `isEnabled`，但操作入口不直观，也未表达“从路由池剔除但保留配置及历史”的业务语义。
- 服务端批量解析选项已支持 `recordIds`，批处理服务会按该 ID 列表执行；前端的批量解析对话框尚未传递该参数。
- 字段运行记录已具备状态、耗时、输入/输出令牌和字段快照；模型使用事件具备模型、记录、字段、操作、耗时和令牌。指标功能应优先复用这些事实数据，不能以字段类型名称或图片开关等前端配置推断实际 AI 调用。
- 既有“全部批量解析”行为保持不变。定向解析作为独立动作，避免用户勾选几条记录后意外执行全任务。

## 交付范围

### A. 模型池验证与剔除

#### A1. 统一验证接口与服务

1. 将当前与特定免费池绑定的验证编排下沉为通用模型池成员验证服务。
2. 新增面向池成员的批量验证接口，输入为模型成员 ID 列表和可选的“验证通过后启用”确认；单次最多 50 个成员。
3. 服务端必须校验成员存在、未重复、可被当前池管理，并逐个返回结果，不能因某一个模型失败而丢失其他模型的验证结果。
4. 验证结果至少包含成员 ID、通过/失败、能力状态、验证时间、错误类别和用户可读错误摘要。
5. 验证只更新能力状态及运行健康信息；除用户明确勾选“通过后启用”外，不得改变 `poolEnabled` 或 `isEnabled`。

#### A2. 明确“剔除”语义

1. 本期“剔除”定义为从当前用途的路由候选池中移除，即设置 `poolEnabled = false`；不删除模型配置、供应商配置、密钥引用、历史分析运行或模型使用事件。
2. 增加剔除原因与时间字段。原因采用预设项“验证失败”“稳定性差”“额度/限流”“人工维护”以及可选补充说明，便于后续排查。
3. 提供“恢复入池”动作；恢复后仍需要重新验证，不能直接把过期或失败模型视为可路由。
4. 批量剔除前显示模型数、当前用途和影响提示。剔除最后一个可用模型时允许执行，但必须明确提示该用途会进入未就绪状态，不能静默回退到付费模型或其他用途模型。
5. 验证失败、短暂网络错误、限流和冷却仅改变健康状态或冷却状态，不自动剔除。剔除必须由用户显式确认。

#### A3. 模型池界面

1. 在模型池表格增加复选框、全选当前筛选结果、清空选择和“已选 N 个”计数。
2. 增加操作入口：验证已选、验证失败/过期项、剔除已选、恢复已选；不可操作状态需说明原因。
3. 每行显示可扫描的状态：在池/已剔除、已验证/未验证/已过期/验证失败、最近验证时间、最近失败摘要及剔除原因。
4. 批量操作结束后保留未成功项的选中状态，并刷新列表与就绪状态；成功项是否保留按操作类型确定，避免用户误以为请求未执行。
5. 既有模型编辑面板继续用于高级配置；新增快捷动作不得复制或绕过原有的输入校验。

### B. 批量解析记录多选

#### B1. 选择模型与交互

1. 新增记录选择状态 hook，作用域为 `jobId + sectionId + 当前筛选条件`。
2. 支持单条勾选、全选本页、取消本页、清空全部和跨页保留选择。切换任务、板块或筛选条件时清空选择，防止把不可见记录误带入新上下文。
3. 复选框点击和键盘操作不得触发行点击详情；列表刷新时仍存在且同作用域的已选 ID 可保留，已删除或不再匹配的记录需自动移除并更新计数。
4. 在记录列表操作区显示“已选择 N 条”，并新增“解析已选”动作；未选择记录时该动作不可用或不给出可误解的全量执行语义。
5. 原有“批量解析”继续表示按当前任务的既有范围执行，文案和确认对话框必须与“解析已选”区分。

#### B2. 定向执行链路

1. “解析已选”复用现有并发数、批次大小、付费令牌预算对话框，并在确认区明确显示本次选中记录数。
2. 前端将去重后的 `recordIds` 传入现有批量执行请求；服务端再次校验这些记录均属于当前任务，并拒绝空列表、重复 ID、越权 ID 或超过约定上限的请求。
3. 服务端只处理已选择且处于允许重跑状态的记录；返回或轮询结果必须区分“选中数、可执行数、已跳过数、完成数、失败数”。
4. 执行被拒绝、网络失败或启动失败时保留选择；任务成功受理后保留选择直到用户清空或切换上下文，避免异步刷新造成误操作。
5. 定向运行仍使用既有任务锁、取消、暂停、模型预算、重试和进度机制，不能创建绕过这些约束的第二套执行器。

### C. 板块解析速度与 AI 字段合理性校验

#### C1. 指标定义

以可筛选的时间范围为单位，默认最近 30 天；所有比率同时显示样本数和数据覆盖情况。

| 范围 | 指标 | 口径 |
| --- | --- | --- |
| 板块 | 执行记录数、完成/失败/待复核/跳过数 | 字段运行和记录最终状态，按板块归属汇总 |
| 板块 | 平均、P50、P95 解析耗时 | 采用有 `durationMs` 的字段运行；样本不足时不计算 P95 |
| 字段 | 调用数、成功率、待复核率、失败率 | 以字段运行事实为准，不以配置是否启用替代 |
| AI 字段 | 模型请求数、模型分布、切换/冷却/额度事件、输入/输出令牌 | 以模型使用事件和字段运行中实际模型快照为准 |
| AI 字段 | 单次字段运行的模型请求数 | 用于发现异常重试或不必要的多模型回退，需与正常容错尝试区分 |

“合理性”是提示分类，不是自动配置动作。每个 AI 字段输出“正常”“关注”“样本不足”之一，并列出命中的规则与原始指标。

#### C2. 合理性规则

1. 统计只覆盖实际触发模型路由的字段。为执行类型注册表补充明确的“是否消耗模型”元数据，不能靠前端字段名称、图片开关或提示词是否为空猜测。
2. 样本少于默认最小样本量 20 时，速度和失败率仅展示原始数据并标记“样本不足”；不得用单次慢请求给出稳定性结论。
3. 速度阈值、失败率阈值、待复核率阈值和每逻辑字段运行的预期模型请求数配置为可审计的系统阈值，初始建议值为：P95 超过 30 秒、失败率达到 10%、待复核率达到 30%、平均模型请求数超过 1.5。不同业务板块可在确认基线后覆盖。
4. 命中慢、失败高、待复核高、异常多次路由、令牌使用缺失或模型调用为零时，报告应写出具体原因和建议排查方向，不能只给颜色标记。
5. 缓存命中、用户取消、明确跳过和历史运行缺失耗时必须分开计数，不能混入“模型慢”结论。
6. 指标页不得发起模型调用、写入解析结果或自动改变模型池和字段开关；它仅读取运行和使用事件。

#### C3. 数据、接口与界面

1. 新增板块效能查询服务与只读 API，按时间范围、板块和可选任务筛选，并在服务端完成聚合，避免向浏览器传输完整运行日志后再计算。
2. 新增必要索引或只增迁移，覆盖字段运行的创建时间、记录任务归属、字段板块归属以及模型使用事件的字段/创建时间查询。既有迁移保持冻结。
3. 对旧数据中缺失耗时、令牌或字段关联的数据返回覆盖率与“历史数据不完整”说明，不伪造补数。
4. 在板块配置或板块详情中提供“效能检查”入口，包含时间范围、板块概览、字段明细、模型使用明细、规则命中原因和空态。
5. 指标页支持按异常状态筛选和按耗时/失败率排序；原始模型使用事件保留现有独立查看能力，作为追溯入口。

## 实施顺序

1. **冻结口径与补齐测试夹具。** 确认允许定向重跑的记录状态、最大选中数、剔除原因枚举、指标阈值和最小样本量；先为服务层写失败、边界、数据缺失与跨任务 ID 的测试。
2. **实现模型池通用验证和剔除数据契约。** 新增只增迁移、共享类型、服务和路由；保留首启免费池接口作为对通用服务的调用方，避免两套验证逻辑漂移。
3. **实现模型池批量操作界面。** 增加选择、状态、确认和结果反馈，并验证就绪状态在剔除/恢复后正确更新。
4. **接通记录多选与定向批量解析。** 增加选择 hook 和工具栏，向既有批量请求透传 `recordIds`，补足服务端 ID 归属、去重和允许状态校验。
5. **实现效能聚合与报告界面。** 先实现可测试的服务端聚合和阈值分类，再添加板块入口、筛选、排序和明细。
6. **回归与试运行。** 用包含成功、失败、待复核、限流、缓存和跨页选择的固定测试数据验收；在真实但脱敏的小批量任务中比对页面统计与原始事件。
7. **更新运行文档。** 补充指标口径、阈值调整、模型恢复、定向批量处理和异常处置说明；将本计划在完成后移入 `docs/archive/`。

## 测试与质量闸门

- 服务层：模型验证、剔除/恢复、最后可用模型提示、`recordIds` 归属与去重、状态过滤、指标聚合、分位数、样本不足、缺失数据、AI/非 AI 字段区分。
- 路由层：请求参数上限、非法 ID、跨任务 ID、空 ID 列表、只读指标查询和错误响应。
- 客户端：选择作用域、跨页保留、筛选清空、复选框不打开详情、定向/全量动作区别、启动失败保留选择、统计空态与异常态。
- 端到端：至少覆盖一次“验证失败后剔除再恢复验证”、一次“跨页选择后仅解析所选记录”、一次“字段慢/失败高被报告且不自动改配置”。
- 交付前执行：`npm test`、`npm run typecheck`、`npm run lint`、`npm run build`、`npm run db:check`、`npm run smoke`、`npm run check:installation` 和 Markdown 链接检查。

## 验收

以 [验收标准](operational-efficiency-acceptance-criteria-2026-09-17.md) 为唯一验收口径。上线前必须同时满足功能验收、数据口径验收、异常处理验收和全部质量闸门；任一模型验证、定向记录解析或指标查询出现跨任务数据访问，视为阻塞缺陷。

## 回退

1. 所有数据库变更只新增迁移；回退优先关闭新入口或恢复旧路由调用，不修改已冻结迁移。
2. 模型剔除是可逆的 `poolEnabled` 状态变更，恢复入池后重新验证；不得通过删除配置回退。
3. 记录多选仅改变请求参数和前端状态。出现问题时隐藏“解析已选”入口，保留原“批量解析”全量流程。
4. 指标功能为只读。出现聚合性能或口径问题时下线效能入口和 API，不影响解析执行、模型路由或历史运行数据。
