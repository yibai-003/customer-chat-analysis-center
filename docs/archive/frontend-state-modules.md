# 前端状态模块拆分

## 已实现结构

`App.tsx` 从约 1080 行降至 223 行，保留工作台和详情展示。界面的状态与操作由实际接入的模块提供：

| 模块 | 职责 |
| --- | --- |
| `useWorkspaceController` | 任务列表、当前板块、全局刷新、任务操作与模块协调 |
| `useRecordWorkspace` | 分页、筛选、页码纠正、详情加载、草稿、请求编号和编辑版本 |
| `useAnalysisPolling` | 轮询定时器、串行请求、暂停/恢复、终态停止和卸载清理 |
| `useImportWorkflow` | 选择文件与板块、预览、确认导入和完成回调 |
| `useReviewSave` | 保存互斥、保存结果版本检查、立即更新详情/列表和刷新任务计数 |
| `api.ts` | 统一读取接口 envelope 与 HTTP 错误 |

工作台通过 `useWorkspaceController` 调用上述 hooks，没有只新增未使用的工具。旧的未接入 App 的 `usePollingTimer` 及其两个测试由实际轮询模块和新生命周期测试替代，原 App 的 30 个测试保留。

## 状态保护

- 保留任务 generation、操作编号、查询身份、详情请求编号及编辑版本；旧任务和旧页面响应不提交到新任务。
- 新分页/详情请求、替换导入预览及卸载会 abort 相应读取请求；列表刷新和字段配置加载也会在过期或卸载后停止提交。
- 轮询每次等待异步工作结束才排下一次；暂停后恢复不会与未结束的旧轮询并发。同步回调抛错和异步失败都进入错误处理并释放运行标志。
- 轮询使用最新刷新回调，避免长生命周期定时器一直使用旧渲染闭包。
- 草稿标记阻止后台刷新覆盖正在编辑的详情；保存失败保留草稿，保存期间切换记录不会把旧结果写入新记录。
- 保存通过 ref 防止同一帧连续点击发出重复请求；成功后先更新当前记录，再刷新任务汇总。
- 已提交的后台导入/模型分析不会因为卸载前端而自动取消；取消业务任务仍使用任务取消按钮，避免把网络断开等同于服务器业务撤销。

固定头部、一屏左栏、约 20% 右栏和详情布局 JSX/CSS 均沿用原实现。本阶段没有改后端接口、数据库结构、模型配置或知识快照。
