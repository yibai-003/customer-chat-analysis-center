## 3. 第一阶段：真实状态、请求边界与任务恢复

### R01 / R04：统一状态语义

1. 单条分析返回真实记录状态和字段结果计数。HTTP 成功仅代表请求处理完成，业务结果必须通过状态表达。
2. 定义并输出记录统计：`total`、`pending`、`processing`、`completed`、`needsReview`、`failed`；两者不可混淆：
   - 已处理进度 = completed + needsReview + failed；失败仍计为已尝试处理。
   - 成功数 = completed；复核数独立展示，不能为了显示 100% 把复核改成成功。
3. 字段统计按每个记录、每个字段的最新运行计算，相同时间以持久化顺序打破平局。增加 needsReview、skipped 统计。
4. 一次批量结束从数据库统一结算；不为适应 mock 而让生产逻辑退回内存统计。测试替身应真实落入代表性的运行记录。
5. 无失败但仍有待处理记录时回到可继续状态；已取消/暂停优先保留。全部处理完但存在业务复核时，可保留任务 completed，同时明确提示“处理结束，仍有待复核”。
6. 字段重试只改变目标字段及对应记录的真实结算，不以一次成功把其他失败字段覆盖为记录成功。
7. 人工复核确认与模型原始运行分开保存：人工确认不篡改历史模型错误；任务统计体现当前记录状态。复核保存与批量执行冲突必须有明确限制或版本校验。

验收：

- [ ] 单条字段失败时接口不返回业务 completed。
- [ ] 19 条全部 needs_review 时显示处理 19/19、成功 0、待复核 19。
- [ ] 1 条成功、6 条失败、10 条 pending、2 条需复核时不能标为全任务完成。
- [ ] 暂停、取消、重试、刷新后统计都与数据库一致。
- [ ] 并发复核与模型完成不会静默覆盖用户已保存结果。

### R02 / R03：有界请求与有所有者的任务锁

1. 请求超时覆盖连接、响应头、完整响应体读取与解析；在整个操作完成后清理定时器。连接测试使用同一有界传输层。
2. 按已确认策略：首次请求之外最多自动重试 2 次，等待 5 秒、15 秒。仅网络、超时、408、429、5xx 可重试；证书/鉴权/参数错误不盲目重试。
3. 对 Retry-After 设明确上限，增加轻微抖动；重试次数、备用模型次数与总墙钟时间共同有界，避免多层重试相乘。
4. 取消传递 AbortSignal 到模型请求、等待与字段调度。取消后不新增后续字段/记录；暂停只停止新记录，允许已在途记录完成。
5. 增加专用 `run_started_at`、`heartbeat_at`、`run_finished_at`，统一 UTC 毫秒时间或显式日期转换。业务 updated_at 不兼作租约。
6. 单实例通过进程级锁禁止第二个实例访问同一运行数据库；取得独占所有权后，启动即恢复旧进程遗留锁，无需等待 15 分钟。
7. 锁续期、结果提交、释放均校验 run_token。旧执行器不得释放新运行的锁，不得在取消/超时后写回迟到结果。
8. 恢复同时处理遗留 processing 记录并重算任务；不要只清 jobs.run_token。

验收：延迟响应头、响应体中途停住、429、网络断开、取消等待、取消在途请求、进程强制退出后立即重启、同库双实例、旧 token 迟到写入。测试用本地假服务和可控时钟，不依赖供应商或真实长时间等待。

| 顺序 | 交付单元 | 依赖 |
| --- | --- | --- |
| 1 | 状态语义与模型请求边界 | 当前基线 |
| 2 | 已验证的备份/完整恢复机制 | 在修改存储前完成 |

| 5 | 前端实际状态拆分、同步故障恢复 | 后端状态约定稳定 |
| 6 | 真机业务验收、运行维护与交付报告 | 前述关键修复通过 |

每个单元使用独立分支或独立提交，修改前检查工作区和运行任务。数据操作用隔离测试库；真实维护前先确认备份可恢复。修改源码不能解释为数据库“自动产生”的变化。

验证规则：运行与变更相匹配的测试，合并前完成全量测试、类型检查和构建；数据库变更另做旧库升级/回滚测试，界面变更检查桌面和窄屏。失败先修，不将失败状态推送主分支，不改生产行为仅为满足不完整的测试替身。

PowerShell 每条验证命令之后立即检查退出码，例如：

```powershell
npm.cmd test
if ($LASTEXITCODE -ne 0) { throw '测试失败，停止发布' }
npm.cmd run typecheck
if ($LASTEXITCODE -ne 0) { throw '类型检查失败，停止发布' }
npm.cmd run build
if ($LASTEXITCODE -ne 0) { throw '构建失败，停止发布' }
```

发布前审查精确文件列表、备份/快照差异和敏感数据；不要使用无差别 git add。当前用户的知识快照改动另行同步。代码通过后再构建并重启；有在途任务先排空或正常暂停，不按端口直接杀死未知进程。

回滚：前端可恢复上一构建；后端无 schema 变化可切回上一提交；有 schema 变化必须匹配数据库版本并用已验证备份恢复，保留升级后数据副本。回滚不是 reset 工作区或删除当前数据库。
