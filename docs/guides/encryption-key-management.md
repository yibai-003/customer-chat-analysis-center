# 独立加密密钥与旧数据迁移

> **文档状态：** 当前有效
> **适用对象：** 系统管理员
> **维护基准：** 2026-09-22 内网版本

## 当前行为

新安装通过官方入口启动，取得数据库实例锁后，在数据库同级目录生成 `.secrets/<数据库文件名>.key.json`。默认是 `data/.secrets/app.db.key.json`。密钥来自 32 字节加密安全随机数，每个数据库独立；不再为新环境使用代码中的固定密钥。

加密算法保持 AES-256-GCM，随机 IV；保留旧版字符串到密钥字节的派生规则，避免无意改变已有独立 `ENCRYPTION_KEY` 的含义。

显式 `ENCRYPTION_KEY`（系统环境变量优先于项目 `.env`）仍优先，须为独立的至少 32 字符值。该配置无法解密当前模型凭据时启动拒绝，不自动更换或覆盖数据。旧示例占位值按未配置处理；显式填入旧固定值或过短值会拒绝，应先移除该配置并执行旧默认密钥迁移，或恢复正确的独立密钥。

已有模型凭据但本地密钥文件缺失时，不会自动生成替代密钥。密钥格式损坏、不匹配、符号链接、目录联接及硬链接也会被拒绝。Windows 新文件关闭权限继承，仅当前账户与 SYSTEM 可访问；其他系统使用目录 0700、文件 0600。这是本机文件权限保护，密钥文件本身不是二次加密的保险库。

`.secrets/` 与 `*.key.json` 已列入 Git 忽略规则；维护命令跳过 `.secrets`。状态命令、迁移报告和日志不输出密钥或 API Key 明文。

## 旧默认密钥迁移

先只读检查：

```powershell
npm.cmd run keys:migrate -- --status
```

输出来源、模型数量、是否可解密、是否存在未完成迁移和默认密钥迁移是否可用。默认不执行写入。使用已有独立环境密钥的数据库无需运行此迁移，继续保管原密钥即可；本命令不提供任意自定义密钥轮换。

确认旧默认密钥迁移可用后：

```powershell
npm.cmd run backup
# 停止服务和守护进程，确保没有运行中/待恢复任务
npm.cmd run keys:migrate -- --apply
npm.cmd run keys:migrate -- --status
npm.cmd run start
```

迁移持有同一数据库实例锁，拒绝在服务运行时执行。先检查数据库版本、完整性、外键及未完成任务；用旧密钥验证所有凭据，再创建并验证 `数据库目录/backups/key-migrations/before-key-*.db` 保护快照，该目录不受常规备份数量清理影响。保护快照不包含业务文件，完整恢复仍使用完整备份包。

先安全保存带 `legacyMigrationPending` 标记的新密钥，再在一个数据库事务中重加密全部凭据并验证往返一致性，提交后清除标记。仅更新模型凭据密文，不改模型地址、名称、用途、能力检测结果、知识库、提示词或业务记录，不调用供应商接口。

中断处理：

- 保护备份失败：不生成新密钥，不重加密。
- 密钥已准备、数据库事务未提交：原密文保留，正常启动拒绝，重新运行迁移继续使用已准备密钥。
- 数据库已提交、完成标记未写入：启动或重复迁移验证全部凭据能用新密钥读取后清除标记。
- 任一凭据损坏或使用未知旧密钥：停止并保留原数据，不做部分迁移。
- 已完成：重复执行报告 `already-migrated`，不会再次生成密钥或改写凭据。

不要删除 pending 密钥文件来“重试”；它可能是已提交数据库唯一匹配的密钥。

## 备份、换环境与回退

完整业务备份刻意不包含密钥。需要单独安全备份当前 `.secrets/<数据库文件名>.key.json`，或原独立 `ENCRYPTION_KEY`，并标明它适用的数据库/备份批次。仅把代码和知识快照推到 GitHub 不能恢复模型凭据；禁止把该密钥文件或含真实数据的备份推送 GitHub。本次没有代用户上传或复制密钥到外部存储。

恢复迁移后的完整包到新目录后，先将匹配的密钥文件放到恢复数据库旁的 `.secrets` 目录。默认恢复数据库是 `data/app.db`，对应文件名为 `data/.secrets/app.db.key.json`；数据库改名时密钥文件名也须对应。使用独立环境密钥的环境则保留原值。启动会先验证解密，缺失或不匹配时拒绝运行，不重建模型配置。切换前用 `npm run restore:verify -- <恢复目录>` 验证数据库、文件引用、知识快照与密钥解密全部通过。

切换 Windows 账户或机器时，使用目标账户安全复制密钥并限制目标权限；不要给 Everyone 开放权限。原密钥丢失后无法从密文还原 API Key，只能重新配置供应商凭据。

回退到迁移前代码需要搭配迁移前数据库，建议按完整恢复流程恢复到另一目录，保留当前数据。不要只切回旧代码继续打开已重加密的数据库。迁移前保护快照仍使用旧默认密钥，必须按敏感备份保管；恢复这种历史数据库时使用旧默认迁移流程，不能搭配当前新密钥强行启动。
