# 数据库迁移与进程恢复

## 迁移版本

结构迁移位于 `src/server/db/migrations/`，通过事务执行，成功后写入 `schema_migrations`。

| 版本 | 含义 |
| --- | --- |
| 1 | 旧版历史标记，仅保留，不把它当成结构已完整的证明 |
| 2 | 一次性检查并补齐旧版表/字段，兼容旧版预留字段与知识库结构 |
| 3 | 增加任务运行开始、心跳、结束时间，统一为 UTC 毫秒 |

空数据库从版本 2 开始创建。已有版本 1 的数据库按 2、3 顺序升级。全部待执行迁移在一个事务中完成，失败则回滚本轮全部结构修改与版本记录。遇到高于当前代码的数据库版本，拒绝继续运行。

升级前在数据库旁 `backups/migrations/` 创建并校验保护数据库备份；它独立于常规完整包的保留清理。升级前仍建议执行 `npm.cmd run backup`，保留数据库与业务文件的完整恢复包。

默认板块和默认字段放在独立 `seed.ts` 中，仅在板块为空时初始化。已有用户字段、提示词和 ID 不再因反复启动执行退款默认配置覆盖。正式删除全部板块后，下次初始化会重新生成默认板块。

`npm.cmd run db:migrations` 与 `npm.cmd run db:check` 均使用只读连接。数据库缺失会报错，不会新建或升级数据库。结构升级只由初始化流程执行。

## 迁移冻结

已编号迁移（`002` 至 `014`）自 2026-09-17 起冻结：迁移一旦合入并应用到任何数据库，只允许新增更高版本，不允许修改原文件。运行器按版本号记录执行结果，修改已应用的迁移不会重新执行，会造成数据库与仓库定义不一致（迁移 `007` 曾因此让真实库缺失知识元数据，只能通过 `npm run knowledge:restore` 修复）。

- `src/server/db/migrations/migrations.lock.json` 记录每个已编号迁移的源文件哈希，`migrations-immutability.test.ts` 校验；修改冻结迁移即测试失败。
- 新增迁移必须在同一提交中把新文件哈希追加到锁文件。
- 结构修正一律通过新增迁移实现，禁止顺手修改历史迁移。
- 如确需修改冻结迁移（发布事故），必须显式更新锁文件并在提交信息中说明原因，视为发布级变更。

## 单实例保护

使用 `npm.cmd run start` / `dev` 的入口会先获得数据库独占运行权，然后才加载数据库、执行迁移、启动服务。

实现采用按规范化数据库路径计算的本机回环保护端口（30000–49999）。端口由操作系统持有，不接收业务请求；崩溃或退出时自动释放，避免遗留 PID 文件阻塞恢复。

- 同一路径（Windows 大小写不敏感）不能启动第二个实例，即使配置不同 HTTP 端口。
- 如果计算出的保护端口被其他程序占用，也会安全拒绝启动；检查冲突，不能绕过保护强行运行。
- 不支持把同一数据库通过不同硬链接路径或不同机器共享启动。单实例约束针对本机官方启动入口；嵌入式调用 `createApp()` 的宿主需自行承担生命周期管理。

## 崩溃重启

已获得进程独占权的服务器在 HTTP 监听成功后执行恢复：

1. 把旧进程遗留的 `processing` 记录标记为失败/需复核。
2. 清空遗留运行锁，记录结束时间。
3. 保留任务的暂停和取消状态；旧 processing 任务变为失败。
4. 按数据库真实记录及字段结果重新汇总已完成/失败计数。
5. 保留之前已完成的结果，用户可明确重试失败记录。

不会等待 15 分钟，也不会根据 ISO 与 SQLite 日期字符串的词典序决定是否恢复。后台导入保持既有启动恢复机制；导入流程完整的去重和中断一致性仍需单独强化。

## 运行 token 防护

批量执行携带 AsyncLocalStorage 运行上下文。续心跳和释放锁检查对应 token；记录、字段运行与知识匹配快照写入前也检查所有权。旧 token 的迟到结果不能覆盖新运行，热点沉淀事务中字段写入失败会回滚该事务。

取消仍保持“停止新记录、等待在途记录结束”的现有语义；全链路 AbortSignal 取消是后续工作。不要把本次 token 防护理解为所有模型请求已经能立即中断。

## 发布与回退

先完整备份并排空运行任务 → 停止旧实例 → 更新代码 → 新入口取得独占权 → 迁移 → 启动恢复 → 检查版本与健康接口。

本次升级前的旧实例没有保护端口，因此首次部署必须先停止已确认的旧进程，不可直接旁路启动新实例。版本升级后回退需使用匹配版本的数据备份；不能直接运行旧代码尝试改写新库。

测试覆盖：版本 1 升级、幂等重启、迁移失败回滚、较新版本拒绝、只读 CLI、不创建缺失数据库、双进程互斥、强杀后立即重启恢复、旧 token 迟到写入与锁释放保护。
