# 上传与导入共享磁盘预留

## 行为

同一服务进程的所有 Excel 上传（含知识库上传）与两种 Excel 任务导入共享 `diskReservations`。每次申请检查：实际可用字节 - `MIN_FREE_DISK_MB` 保底 - 其他未写入预留，是否足够。检查和登记同步完成，两个并发请求不能同时获准使用同一份余量。

预留是应用内额度，不是操作系统提前分配文件。默认仍保留 512 MiB 磁盘余量；空间不足/被其他任务占用返回 507，磁盘无法检测返回 503，实际写入超过预算返回 413。

## 生命周期

1. 上传开始用 multipart Content-Length 作为保守上界，并受 `MAX_UPLOAD_MB` 限制；没有有效长度的分块上传按最大文件上限预留。multipart 的表单开销因此可能使估计略大，任务结束释放余量。
2. 每个块写入前重新检查磁盘；实际写入回调完成后，才扣减对应未写入额度。其他任务看到的是实际余量加仍未落盘的预留约束，避免已写数据重复计费。
3. 上传成功落盘后释放该上传剩余额度，已写文件由磁盘真实余量反映。文件校验仍会检查声明解压量加全局预留，不把校验本身视作已分配磁盘。
4. 后台导入在创建 staging 文件前重新申请「源工作簿副本 + 每条记录实际输出图片」预算。同一媒体被多个绘图锚点引用时分别计算，因为当前导入会生成多个文件。
5. 源文件复制与图片提取均走受预算约束的流式写入器；预算不足不创建导入任务结果。成功、失败、超限或客户端中断后关闭文件并释放额度，失败保留原上传源且清理本次 staging。
6. 崩溃后内存额度随进程退出消失，磁盘真实占用不会消失；启动恢复的每个导入都会根据当前文件重新申请，不能继承虚假的空闲空间。

知识导入预览与确认之间采用同盘 rename，不重复写一份文件；它们的上传已经计入预算。SQLite、日志、备份、导出和其他软件的写入目前不申请此池的额度，因此每块写入前仍检查真实磁盘。外部进程可能在检查后占用空间，操作系统写入失败仍会传播并触发清理；这不是多进程文件系统配额。

当前适用范围是本项目单实例、同一 DATA_DIR。多个服务器进程/不同数据库同时使用同盘时需要外部配额或跨进程协调，不能把本地池作为团队并发存储方案。

## 验收（2026-09-14）

- 新增 10 项测试：拒绝重复分配、已写字节抵扣、非法数字、外部磁盘变化、超预算写入、真实 HTTP 并发上传与断开清理、两种导入器重复图片计数及失败恢复。
- 并发测试使用本地 HTTP 与隔离数据目录：第一个请求占额时第二个返回 507，第一个断开后额度归零，新请求可成功上传。
