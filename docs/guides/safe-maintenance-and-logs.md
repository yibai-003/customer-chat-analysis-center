# 安全清理与日志轮换

> **文档状态：** 当前有效
> **适用对象：** 系统管理员
> **维护基准：** 2026-09-22 内网版本

## 临时文件清理

默认只预览，不删除文件，不创建或升级数据库：

```powershell
npm.cmd run maintenance
# 等价于 npm.cmd run maintenance -- --dry-run
```

输出候选文件相对路径、字节数、保留原因计数和任务状态。仅扫描 `DATA_DIR/uploads`、`knowledge-previews`、`job-staging` 中的普通文件，默认保留 14 天；`CLEANUP_RETENTION_DAYS` 必须是 1–3650 的整数。

实际清理须先备份并查看预览，然后停止服务，再执行：

```powershell
npm.cmd run backup
# 停止当前服务后重新扫描并删除符合条件的文件
npm.cmd run maintenance -- --apply
npm.cmd run start
```

实际执行会获取与服务相同的数据库实例锁。服务未停止、保护端口被占用、存在未恢复的运行记录/排队导入、数据库版本不匹配或完整性/外键检查失败时拒绝删除。不会为清理而清空任务锁、执行迁移或强制终止服务。

清理规则：

- 核对任务原始 Excel、记录截图、文件导入来源、知识库导入来源四类持久化引用，保留被引用的文件及数据库/SQLite 附属文件。
- 按每个文件的时间判断；旧目录内的新文件仍保留，不递归删除目录，空目录暂时保留。
- 跳过符号链接、Windows 目录联接、硬链接和特殊文件；清理根目录或其祖先有联接时拒绝执行。
- 删除前再次检查绝对路径范围、文件身份、大小及时间；扫描超过 10 万项时停止，不开始删除。
- 不清理 `jobs`、`imports`、`knowledge-imports`、`exports`、`backups`、知识快照或日志。

预览结果不是锁定的删除清单；`--apply` 会重新扫描。文件删除没有跨文件事务，中途磁盘/权限错误会停止并报告失败，已删除的临时文件不会自动回滚。此机制针对本地单实例运行；操作时不要同时用其他程序修改数据目录。

## 运行日志

`npm run start`、`npm run dev` 和守护脚本统一进入 `src/server/launcher.ts`。启动器捕获实际服务进程的标准输出与错误输出，终端仍显示同样内容，文件保存在实际配置的 `DATA_DIR/logs`：

| 文件 | 用途 |
| --- | --- |
| `server.out.log` | 当前标准输出 |
| `server.err.log` | 当前错误输出 |
| `server.out.1.log` / `server.err.1.log` | 最新归档；数字越大越旧 |

默认 `LOG_MAX_MB=10`（1–100 整数）、`LOG_RETENTION=7`（1–30 整数），分别控制每个新日志文件大小和每路归档数量。达到大小限制或 UTC 日期变化时，在下一次写入前轮换；没有日志写入时不产生空归档。默认两路新日志合计最多约 160 MiB。重启追加当前文件，降低保留数量后在下一次轮换清理多余受管归档。

旧版其他名称的日志不自动删除，既有超大当前日志轮换时完整保留为归档，不直接截断。日志路径及归档槽位拒绝链接和硬链接；独立日志实例锁防止两个启动器同时操作同一组日志。

输出使用流背压，单次写入按容量分段，不累计无限内存队列。日志落盘失败会停止服务子进程并返回非零退出码；子进程失败码也会传回启动脚本，供有界重启使用。手工直接运行 `src/server/index.ts` 会绕过日志启动器，请使用官方 npm 命令。

本阶段没有安装或启用开机守护任务；仍不提供团队认证或远端日志服务。独立密钥与默认密钥迁移已由后续单元完成，见 `encryption-key-management.md`。清理始终跳过 `.secrets` 目录。
